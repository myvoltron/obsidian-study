## 1. Encoder–Decoder 구조
**Encoder**는 입력을 특징·문맥을 담은 수치 표현 (임베딩)으로 바꾸고, **Decoder**는 이 표현을 바탕으로 출력을 생성한다. 입력·출력 모달리티에 따라 Encoder와 Decoder를 교체·결합할 수 있다.

### 1.1 영상·언어 Encoder와 Decoder

| 구성 | 입력 | 출력과 대표 모델 |
|---|---|---|
| **영상 Encoder** | 이미지·영상 | CNN이나 ViT로 시각 특징을 추출해 고정 크기 임베딩을 만든다. |
| **언어 Encoder** | 단어·토큰 | RNN (LSTM·GRU)이나 BERT·Transformer로 문맥 수치 표현을 얻는다. |
| **영상 Decoder** | 잠재 표현 | CNN (VAE·GAN), Transformer, 확산 모델로 목표 해상도 이미지를 생성·복원한다. |
| **언어 Decoder** | 문맥과 앞선 토큰 | RNN이나 Transformer로 다음 토큰을 예측해 텍스트를 생성한다. |

### 1.2 Encoder와 Decoder의 멀티모달 결합

| 과제 | 조합 |
|---|---|
| **이미지 캡셔닝** (이미지 → 텍스트) | 영상 Encoder → 언어 Decoder |
| **텍스트–이미지 생성** (텍스트 → 이미지) | 언어 Encoder → 영상 Decoder (생성 모델) |
| **시각적 질문 답변** (VQA) | 영상 Encoder + 언어 Encoder → 언어 Decoder |

## 2. Encoder–Decoder 동작 원리
### 2.1 특징 추출·문맥 벡터와 Attention
- **특징 추출** — 영상의 경계·질감·형태나 텍스트의 의미 관계를 수치 특징으로 압축한다.
- **문맥 벡터 생성** (Context Vector) — 출력에 필요한 특징을 요약하며, 디코딩 시 클래스 레이블이나 텍스트 같은 조건을 함께 줄 수 있다.

| 방식 | 작동 방식 |
|---|---|
| **Global Average Pooling** | 채널마다 공간 위치의 평균을 구해 압축한다 (위치 정보는 줄어든다). |
| **Flattening** | 특징 맵의 개별 값을 유지한 채 1차원 벡터로 펼친다. |

- **Attention의 역할** — 출력에 관련된 입력 특징을 고르는 **정보 선택**, 출력 토큰과 관련 영상 영역·위치를 잇는 **입출력 정렬**, 생성 시점마다 가중치를 바꾸는 **문맥의 동적 갱신**을 수행한다.

### 2.2 손실 함수·학습 목표와 평가

| 구분 | 언어 생성 (번역·캡셔닝) | 이미지 생성 (복원·합성) |
|---|---|---|
| **손실 함수** | **Cross-Entropy** (토큰 예측 확률과 정답 분포 차이) | **MSE** (기준 이미지와 출력의 픽셀값 제곱 오차 평균) |
| **학습 목표** | **최대우도추정** (MLE, 정답 시퀀스 확률 최대화) | **적대적 학습** (GAN의 G·D 경쟁) |
| **평가 지표** | **BLEU** (참조문과 단어·구문 일치), **ROUGE** (참조문 내용 포함·중첩) | **Inception Score** (분류 명확성·다양성 ↑), **FID** (특징 분포 차이 ↓) |

## 3. 영상 주석 생성 1 (Image Captioning)
**이미지 캡셔닝**은 입력 이미지의 내용을 설명하는 텍스트를 생성하는 작업이다.
1. 영상 Encoder (CNN·ViT)가 이미지 영역별 특징을 추출한다.
2. Attention이 앞서 생성한 캡션과 관련된 영역에 높은 가중치를 주어 동적 문맥 벡터를 만든다.
3. 언어 Decoder (RNN·Transformer)가 문맥 벡터와 앞선 토큰으로 다음 토큰을 예측하며, 종료 토큰 (EOS)이 나올 때까지 반복한다.

### 3.1 이미지 캡션의 과제

| 과제 | 어려운 점 |
|---|---|
| **세밀한 물체 인식** | 복잡한 장면에서 작은 물체와 세부 특징을 놓치기 쉽다 (객체 분할 결과를 Attention 단서로 활용 가능). |
| **장거리 의존성** | 떨어져 있는 물체와 배경의 관계를 파악해야 한다 (RNN은 먼 연결이 어렵고 Transformer는 위치 정보 필요). |
| **모호성 처리** | 한 이미지에 여러 설명이 가능하므로 상황과 문맥에 맞는 정보를 골라야 한다. |

## 4. 영상 주석 생성 2
- Pokémon BLIP Captions의 이미지·캡션을 모델에 맞게 전처리한 뒤, Hugging Face에서 가져온 사전학습 **GIT**를 Fine-tuning한다.
- **GIT** (Generative Image-to-text Transformer)는 영상 Encoder와 텍스트 Decoder 모두에 Transformer를 사용한다.

## 5. 네트워크 응용
- **설명·검색·보고** — 시각 보조 도구·소셜 미디어용 이미지 설명, 생성 캡션 키워드 기반 콘텐츠 색인·검색, 차트·그래프·X선 의료 영상의 자동 보고서 초안 생성에 활용한다.
- **교육·감시·질의응답** — 교육 자료 설명문 생성, 보안 카메라 장면의 사건 자동 기술, 이미지 속 물체·속성·수량에 답하는 **시각적 질문 답변** (VQA)에 적용한다.
