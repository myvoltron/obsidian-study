# 06. 언어 모델 - BERT와 GPT
[[00. 생성형인공지능입문 - 시험 대비 목차|과목 목차]] · [[05. 트랜스포머 2 - ViT와 U-Net|이전 주차]] · [[07. 대결형 생성 네트워크 - GAN VAE Diffusion|다음 주차]]

## 1. BERT 모델

### 1.1 BERT의 구조와 역할

**BERT** (Bidirectional Encoder Representations from Transformers)는 양방향 Transformer Encoder를 사용한다. 큰 텍스트 말뭉치로 앞뒤 문맥을 함께 반영하는 표현을 사전학습한 뒤, 이 표현을 분류나 질의응답 같은 다운스트림 과제에 사용한다.

### 1.2 BERT 입력 표현

- **문장** — 하나의 세그먼트로 취급하는 연속된 텍스트 범위다. 문법적으로 완결된 문장일 필요는 없다.
- **시퀀스** — BERT에 입력하는 전체 토큰 열이다. 한 문장이나 두 문장으로 구성한다.
- **토큰** — WordPiece로 나눈 단어 조각이나 특수 토큰이다. 예를 들어 `playing`은 `play`와 `##ing`으로 나눌 수 있다. 첫 토큰은 `[CLS]`이고, 각 세그먼트 끝에는 `[SEP]`를 붙인다.

| 입력 | 토큰 배열 | 세그먼트 ID |
|---|---|---|
| **단일 문장** | `[CLS] 문장 A [SEP]` | 모두 0 |
| **문장 쌍** | `[CLS] 문장 A [SEP] 문장 B [SEP]` | 첫 구간은 0, 두 번째 구간은 1 |

각 위치의 입력 벡터는 아래 세 임베딩을 더한 값이다.

| 임베딩 | 역할 |
|---|---|
| **Token embedding** | WordPiece나 특수 토큰을 벡터로 나타낸다. |
| **Segment embedding** | 같은 세그먼트에 속한 토큰에 같은 학습 벡터를 더해 문장 A·B를 구분한다. |
| **Position embedding** | 시퀀스에서 토큰이 놓인 위치를 나타낸다. 원래 BERT는 위치마다 학습 가능한 벡터를 사용한다. 원래 Transformer의 위치 인코딩은 삼각함수로 구성된다. |

### 1.3 BERT의 사전학습

레이블 없는 텍스트에서 두 과제를 함께 학습한다.

| 과제 | 입력과 학습 목표 |
|---|---|
| **MLM** (Masked Language Modeling) | 일부 토큰을 가리거나 바꾼 입력을 준다. 선택한 위치의 최종 hidden state와 Softmax 출력층으로 앞뒤 문맥에서 원래 토큰을 예측한다. |
| **NSP** (Next Sentence Prediction) | 문장 쌍의 절반은 실제로 이어지는 문장으로, 나머지는 두 번째 문장을 무작위로 뽑아 만든다. `[CLS]`의 최종 hidden state로 IsNext와 NotNext를 분류한다. |

MLM은 **전체 토큰 중 약 15%**를 예측 대상으로 고른다. 선택된 토큰의 **80%**는 `[MASK]`로, **10%**는 무작위 토큰으로 바꾸고, **10%**는 원래 상태로 둔다. 세 경우 모두 원래 토큰을 정답으로 사용한다. 일부를 일반 토큰처럼 보이게 두면 Fine-tuning과의 입력 차이가 줄어든다. Encoder가 겉보기로 예측 대상 위치를 구분하기 어려워 모든 위치의 문맥을 반영하게 한다. 전체 토큰 가운데 무작위 치환 대상은 약 1.5%다.

### 1.4 BERT Fine-tuning

사전학습한 Encoder에 과제별 출력층을 붙이고, 레이블이 있는 과제 데이터로 Encoder와 출력층을 함께 학습한다. 과제별 학습 데이터와 출력은 [[#3.3 Fine-tuning 적용 사례|Fine-tuning 적용 사례]]에 모았다.

### 1.5 BERT의 장점 및 성능

| 장점 | 이유 |
|---|---|
| **전이학습** | 사전학습으로 얻은 언어 표현을 재사용해 적은 양의 과제 데이터로도 학습할 수 있다. |
| **양방향 문맥** | 각 토큰을 해석할 때 양쪽 문맥을 참고해 한 단어의 의미를 문장에 맞게 파악한다. |
| **문장 수준 이해** | 문장 또는 문장 쌍의 표현으로 감성 분석, 의도 분류, 문장 관계 판단을 할 수 있다. |
| **다국어 지원** | 여러 언어로 사전학습한 BERT는 언어 간 표현을 공유해 다른 언어의 과제에 적용할 수 있다. 성능은 언어별로 달라질 수 있다. |

### 1.6 BERT의 단점 및 한계

| 한계 | 이유와 대응 |
|---|---|
| **모델 크기** | 파라미터가 많으면 저장 공간과 메모리를 많이 사용해 모바일 등 자원이 제한된 환경에 적용하기 어렵다. |
| **추론 속도** | 계산량이 커 실시간 처리가 어려울 수 있다. 경량 모델이나 하드웨어 가속을 사용할 수 있다. |
| **사전학습 데이터 의존성** | 목표 분야의 용어와 문체가 사전학습 데이터에 충분히 담기지 않으면 관련 데이터로 추가 학습할 수 있다. |
| **입력 길이 제한** | 원래 BERT의 입력은 최대 512토큰이다. 더 긴 문서를 자르거나 나누면 멀리 떨어진 내용의 관계를 놓칠 수 있다. |

## 2. GPT

### 2.1 GPT의 구조와 입력

**GPT** (Generative Pre-trained Transformer)는 **Decoder-only** 구조의 언어 모델이다. 입력 텍스트를 단어 조각·문장부호 등을 포함하는 토큰으로 나누고, 토큰 임베딩에 위치 정보를 반영한다.

Decoder 블록에는 Masked Multi-Head Self-Attention, FFN, LayerNorm이 들어간다. Causal mask는 각 위치가 미래 토큰을 참조하지 못하게 한다. 출력층은 현재 표현을 어휘별 다음 토큰 확률로 바꾼다.

### 2.2 GPT의 사전학습과 생성

| 과정 | 다음 토큰을 사용하는 방식 |
|---|---|
| **사전학습** | 실제로 이어지는 토큰을 정답으로 삼는다. 다음 토큰의 예측 분포와 정답 사이의 Cross-Entropy를 계산하고, 손실의 기울기를 이용해 파라미터를 갱신한다. |
| **생성** | 입력에 이어질 토큰을 하나 선택해 뒤에 붙이고, 이어진 토큰 열을 입력으로 사용해 다음 토큰을 예측한다. 이렇게 텍스트를 완성해 응답·번역·요약 등을 생성한다. |

### 2.3 GPT의 장점과 성능

| 장점 | 이유와 활용 |
|---|---|
| **자연스러운 텍스트 생성** | 앞 문맥에 이어지는 문장을 만들어 글 작성·번역·요약에 활용한다. |
| **대화형 응답** | 사용자 입력과 앞선 대화를 조건으로 응답을 생성한다. |
| **빠른 프로토타이핑** | 사전학습한 언어 이해와 생성 능력으로, 추가 학습 없이도 챗봇 등 응용을 빠르게 시험할 수 있다. |
| **모델 규모 선택** | 큰 모델은 복잡한 과제에 유리할 수 있고 작은 모델도 여러 자연어 처리 작업에 쓸 수 있다. 과제 난도와 계산 자원을 고려해 규모를 선택한다. |
| **문맥 활용** | Attention으로 입력 범위 안의 떨어진 위치를 직접 참조할 수 있다. |
| **전이학습** | 사전학습한 모델을 특정 데이터와 과제에 맞게 추가 학습할 수 있다. |

### 2.4 GPT의 단점과 한계

| 단점 | 이유 |
|---|---|
| **출력 변동성** | 확률적으로 토큰을 선택하는 방법을 사용하면 같은 입력에서도 결과가 달라질 수 있다. |
| **긴 입력의 문맥 파악** | 입력 가능한 토큰 수가 제한되고, 범위 안에서도 긴 입력의 모든 관계를 정확히 반영하기 어렵다. |
| **전문 분야 특화** | 일반 텍스트 위주로 학습한 모델은 특정 분야의 전문 지식이나 용어가 부족할 수 있다. |
| **긴 대화의 지속성** | 여러 차례 대화하면서 앞선 발화나 조건이 입력에서 잘리거나 제대로 반영되지 않으면 응답의 일관성이 떨어질 수 있다. |
| **편향** | 학습 데이터에 포함된 사회적·문화적 편향이 응답에 나타날 수 있다. |

### 2.5 BERT·GPT·ELMo 비교

| 모델 | 구조와 문맥 사용 | 사전학습에서 예측하는 것 |
|---|---|---|
| **BERT** | 양방향 Transformer Encoder로 양쪽 문맥을 함께 본다. | 가려지거나 바뀐 위치의 원래 토큰과 두 문장의 연속 여부를 예측한다. |
| **GPT** | Transformer Decoder와 Causal mask로 앞쪽 문맥을 본다. | 실제로 이어지는 다음 토큰을 예측한다. |
| **ELMo** | 2층 LSTM으로 정방향과 역방향 언어 모델을 따로 학습하고 두 표현을 결합한다. | 각 방향에서 주어진 문맥에 이어지는 토큰을 예측한다. |

## 3. Fine-tuning

### 3.1 Fine-tuning이란?

사전학습한 모델을 특정 과제에 맞는 새 데이터로 추가 학습하는 전이학습 방식이다. 이미 학습한 표현을 재사용해 적은 과제 데이터로도 적응할 수 있다.

### 3.2 Fine-tuning 과정

1. 과제에 맞는 사전학습 모델을 선택한다.
2. 과제에 필요한 학습 데이터를 준비한다.
3. 데이터를 선택한 모델의 입력 형식에 맞게 전처리한다.
4. 과제의 목표에 맞춰 모델을 추가 학습한다.
5. 검증 데이터로 평가하며 하이퍼파라미터를 조정한다.
6. 학습한 모델을 저장한다.

### 3.3 Fine-tuning 적용 사례

| 과제 | 학습 데이터 | 사용하는 표현과 출력 |
|---|---|---|
| **감성 분석** | 문장과 긍정·부정 등 감성 레이블 | BERT에서는 `[CLS]`의 최종 표현을 Softmax 분류층에 넣어 감성 확률을 구한다. |
| **텍스트 분류** | 문장·문서·문장 쌍과 과제별 레이블 | BERT에서는 `[CLS]`의 최종 표현을 분류층에 넣어 주제나 문장 간 관계를 예측한다. |
| **개체명 인식** (NER) | 토큰별 인명·장소·기관 등의 레이블 | 각 토큰의 최종 표현으로 레이블을 예측한다. 이전 레이블을 입력으로 넣는 자기회귀 과정 없이 처리하며, 구현에 따라 CRF로 레이블 간 관계를 반영한다. |
| **추출형 질의응답** | 질문·지문과 지문 속 정답 범위 | 질문과 지문을 한 시퀀스로 넣는다. 지문 토큰의 최종 표현으로 정답이 시작하고 끝나는 위치를 각각 예측한다. |
| **텍스트 생성** | 원하는 문체·톤·구조를 담은 텍스트 예시 | GPT 같은 생성 모델을 추가 학습해 원하는 속성의 텍스트를 출력하도록 한다. |

### 3.4 Fine-tuning의 장점

| 장점 | 이유 |
|---|---|
| **적은 레이블로 적응** | 사전학습한 표현이 있어 적은 수의 정답 예시로도 특정 작업을 학습할 수 있다. |
| **일반화** | 기존의 범용 표현을 새 과제에 사용하면 유사한 사례에도 적용하기 쉽다. |
| **시간과 비용 절감** | 처음부터 모델을 학습하거나 많은 레이블을 새로 수집하는 비용을 줄일 수 있다. |
| **다국어 적용** | 다국어 능력이 있는 사전학습 모델을 목표 언어의 데이터로 추가 학습할 수 있다. |

### 3.5 Fine-tuning의 단점

| 단점 | 이유 |
|---|---|
| **과적합** | 작은 훈련 집합에 지나치게 맞추면 처음 보는 사례의 성능이 떨어진다. |
| **데이터 양·품질·대표성** | 정확한 데이터를 충분히 확보하고 실제 사용 사례의 다양성을 반영해야 새 입력에 일반화할 수 있다. |
| **시간과 계산 비용** | 기반 모델이나 과제 데이터셋이 크면 Fine-tuning에도 상당한 학습 시간과 계산 자원이 필요하다. |
| **사전학습 모델 적합성** | 기반 모델이 학습한 표현이나 구조가 목표 작업에 맞지 않으면 추가 학습의 효과가 제한된다. |
| **다른 작업으로의 이전** | 한 작업에 맞춘 결과를 크게 다른 작업에 적용하려면 별도 데이터와 재학습이 필요할 수 있다. |

## 4. Interactive GPT

### 4.1 대화형 GPT의 동작

사용자의 요청과 앞선 대화에 맞춰 응답을 생성한다. 사람이 작성한 모범 응답이나 후보 응답에 대한 선호를 수집해 후속 학습에 반영하면 응답을 지속적으로 개선할 수 있다.

### 4.2 RLHF 학습 과정

**RLHF** (Reinforcement Learning from Human Feedback)는 사람의 선호로 학습한 보상 모델의 점수를 이용해 응답을 선택하는 정책을 개선하는 방식이다. 아래는 SFT와 PPO를 사용하는 학습 흐름이다.

| 단계 | 사용하는 데이터 | 갱신하는 모델 |
|---|---|---|
| **지도 Fine-tuning** (SFT) | 프롬프트와 사람이 작성한 모범 응답 쌍 | 사전학습 언어 모델을 모범 응답에 맞게 학습한다. |
| **보상 모델 학습** | 같은 프롬프트에 대한 후보 답변과 사람이 매긴 선호 순위 | 사람이 선호한 응답에 더 높은 점수를 주도록 보상 모델을 학습한다. |
| **정책 최적화** | 새 프롬프트, 정책 모델이 생성한 응답, 보상 모델이 매긴 점수 | SFT 모델로 초기화한 정책 모델을 PPO (Proximal Policy Optimization)로 갱신해 높은 보상을 얻도록 한다. |

### 4.3 대화형 GPT의 응용

| 응용 | 활용 |
|---|---|
| **고객 지원과 상담** | 문의를 이해하고 해결 방법을 안내하며 반복 문의에 실시간으로 응답한다. |
| **가상 도우미** | 대화 문맥을 활용해 일정·알림을 관리하거나 검색과 스마트홈 제어를 지원한다. |
| **콘텐츠 제작과 아이디어 제안** | 기사·광고·대본·가사의 초안을 만들고 아이디어를 제안한다. |
| **번역과 언어 학습** | 대화 내용을 번역하고 문맥·어휘를 설명하거나 회화 연습을 지원한다. |
| **교육과 자기 학습** | 학습자의 질문에 답하고 이해 수준에 맞춰 설명한다. |

### 4.4 실제 예시

| 서비스 | 활용 |
|---|---|
| **ChatGPT** | 대화 문맥을 이어가며 콘텐츠 기획이나 아이디어 구체화를 돕는다. |
| **Replika** | 가상의 대화 상대가 이전 대화를 참고해 공감형·개인화 응답을 한다. |
| **AI Dungeon** | 플레이어가 행동을 텍스트로 입력하면 그에 맞춰 게임의 이야기가 이어진다. |

## 5. 사람 피드백 학습

### 5.1 사람 피드백 학습이란?

사용자의 지시·평가·교정이나 전문가의 주석을 반영해 모델을 개선하는 방식이다. 주석과 수정안은 원하는 답을 알려주고, 선호 순위는 여러 후보 중 어떤 답이 맥락과 의도에 더 맞는지 알려준다.

### 5.2 피드백을 얻는 방식

| 피드백 | 신호를 얻는 곳 | 예시와 활용 |
|---|---|---|
| **명시적 피드백** | 사람이 직접 제공한 평가·수정·주석 | 객체에 레이블을 붙이거나, 생성 문장을 교정하거나, 응답의 선호 순위를 매긴다. |
| **암묵적 피드백** | 사용자 행동에서 추정한 신호 | 클릭·체류 시간·반복 선택을 관찰해 추천과 개인화를 개선하는 데 활용한다. |

### 5.3 피드백을 학습에 반영하는 방식

| 학습 방식 | 피드백의 쓰임 |
|---|---|
| **지도학습** | 사람이 제공한 정답이나 레이블을 목표로 학습한다. 예를 들어 메일을 스팸·정상으로 표시해 분류 모델을 학습시킨다. |
| **강화학습** | 환경에 행동을 취하고 그 결과로 얻는 보상을 높이도록 학습한다. 예를 들어 자율주행에서는 여러 주행 상황에서 어떤 행동을 선택할지 학습할 수 있다. RLHF에서는 사람 선호로 학습한 보상 모델의 점수를 사용한다. |
| **대화형 학습** | 상호작용에서 얻은 평가와 교정을 후속 학습에 반영한다. 예를 들어 사용자가 챗봇의 답변을 수정한 기록을 활용한다. |

### 5.4 사람 피드백의 사이클과 구현

1. **응답 생성** — 사전학습한 모델이 실제 대화나 과제를 처리한다.
2. **피드백 수집** — 사용자의 평가와 행동, 전문가의 의견을 모은다.
3. **주석·검증** — 레이블·수정안·점수를 붙이고 자료의 일관성과 대표성을 점검한다.
4. **모델 갱신** — 준비한 피드백으로 모델을 추가 학습한다.
5. **평가와 반복** — 갱신한 모델을 검증하고, 새 상호작용에서 얻은 피드백으로 다음 학습을 진행한다.

### 5.5 사람 피드백 학습의 장점

| 장점 | 이유 |
|---|---|
| **성능 개선** | 사람이 제공한 정답·수정·선호는 정확성과 관련성을 높이는 학습 신호가 된다. |
| **적응성 향상** | 새 요구나 오류에 대한 피드백을 다시 반영해 모델을 개선할 수 있다. |
| **편향 완화** | 여러 관점의 피드백으로 특정 집단에 불공정한 결과를 발견하고 줄일 수 있다. |
| **다양한 업무 처리** | 여러 종류의 과제와 실패 사례에서 받은 피드백으로 대응할 수 있는 상황을 넓힌다. |

### 5.6 사람 피드백 학습의 문제점

| 한계 | 이유와 대응 |
|---|---|
| **편향** | 평가 집단의 사회적·문화적 편향이 모델에 반영될 수 있다. 다양한 집단의 의견을 수집한다. |
| **확장성** | 사용량과 과제가 늘면 서로 다른 상황에서 대량의 피드백을 일관되게 수집·처리·통합하기 어려워진다. |
| **주관성과 다양성** | 평가자마다 선호가 다를 수 있다. 공통 지침으로 일관성을 높이면서 다양한 의견을 반영한다. |
| **수집과 검증** | 피드백의 대표성과 관련성을 검증하고 주석 오류를 점검해야 한다. |

### 5.7 실제 적용 사례

| 분야 | 피드백을 반영하는 방식 |
|---|---|
| **언어 번역** | Google 번역과 같은 시스템에서 사람이 교정한 표현을 반영하면 번역의 정확도와 문맥에 맞는 표현을 개선하는 데 도움이 된다. |
| **콘텐츠 생성** | GPT-3 계열의 생성 시스템에서는 글의 문체·일관성·관련성에 대한 사람의 평가와 수정 예시를 반영할 수 있다. 글쓰기와 마케팅, 창작에 사용하는 결과를 개선하는 데 활용한다. |
| **로봇 공학** | 사람이 동작을 안내하고 교정한 사례를 이용해 환경 탐색과 작업 수행을 학습한다. |
| **의료 영상 분석** | 전문가가 영상의 소견이나 모델의 판단을 검토한 결과를 반영해 분석 성능을 개선한다. |

## 6. GPT 환각 — 기출 보충

**환각** (Hallucination)은 사실이나 주어진 근거와 맞지 않는 내용을 그럴듯하게 생성하는 현상이다.

| 원인 | 기술적 완화 방법 |
|---|---|
| **다음 토큰 예측과 사실 검증의 차이** — 문맥상 그럴듯한 토큰을 예측하다 보면 근거가 부족한 주장을 생성할 수 있다. | 검증된 데이터와 피드백으로 Fine-tuning하고, 생성한 주장을 검색·계산·데이터베이스로 대조한다. |
| **학습 데이터의 오류나 지식 부족** — 학습에 잘못된 정보가 들어 있거나 최신·전문 지식이 부족할 수 있다. | **RAG** (Retrieval-Augmented Generation)로 질문과 관련된 문서를 검색해 프롬프트에 넣는다. 검색 결과가 실제로 질문과 관련 있고 신뢰할 만한지도 확인한다. |
| **모호한 질문과 문맥 부족** — 필요한 전제나 근거가 없으면 모델이 빈 부분을 추측할 수 있다. | 필요한 조건과 문맥을 제공한다. 근거가 부족하면 추가로 질문하거나 답변을 보류하게 한다. |
| **자기회귀 생성의 오류 누적** — 잘못 생성한 내용이 다음 토큰의 문맥에 들어가 후속 답변에 영향을 준다. | 중간 또는 최종 주장을 원문과 대조해 잘못된 전제를 찾아 바로잡는다. |

RAG는 응답을 생성할 때 근거를 입력에 추가한다. Fine-tuning은 학습으로 모델의 파라미터를 갱신한다.
