# 06. 언어 모델 - BERT와 GPT

## 1. BERT 모델

### 1.1 BERT 모델이란?

**BERT** (Bidirectional Encoder Representations from Transformers)는 언어 표현을 사전학습하는 양방향 Transformer Encoder 모델이다. 대규모 텍스트로 범용 언어 이해 모델을 학습하고, 이를 목표로 하는 다운스트림 자연어 처리 작업에 사용한다. Google이 GPT에 이어 발표한 모델이다.

### 1.2 사전학습 모델의 아키텍처 비교

| 모델 | 문맥을 학습하는 방식 |
|---|---|
| **BERT** | 양방향 Transformer Encoder를 사용한다. 토큰 일부를 가린 뒤 앞·뒤 문맥을 참고해 원래 토큰을 예측한다. |
| **GPT** | Transformer Decoder로 앞선 문맥의 토큰만 보고 다음 토큰을 예측한다. |
| **ELMo** | 2층 LSTM에서 정방향과 역방향의 언어 모델을 학습하고, 두 방향의 표현을 결합한다. |

### 1.3 임베딩

BERT의 입력 벡터는 각 위치의 **Token embedding + Segment embedding + Position embedding**이다.

| 임베딩 | 역할 |
|---|---|
| **Token embedding** | WordPiece 또는 특수 토큰의 내용을 벡터로 표현한다. |
| **Segment embedding** | 토큰이 속한 문장 A·B를 학습된 벡터로 구분한다. 같은 세그먼트의 토큰에는 같은 벡터를 더한다. |
| **Position embedding** | 시퀀스 안의 위치마다 학습한 벡터를 더한다. 원래 Transformer의 삼각함수 기반 위치 인코딩과 구현 방식이 다르다. |

### 1.4 BERT 모델 학습

레이블이 없는 텍스트에서 양방향 문맥 표현을 사전학습한다. 원래 BERT의 사전학습 과제는 **MLM** (Masked Language Modeling)과 **NSP** (Next Sentence Prediction)다.

### 1.5 사전학습 과제

- **MLM** — 한 방향으로 다음 토큰을 예측하는 언어 모델은 그 위치의 양쪽 문맥을 동시에 사용하기 어렵다. BERT는 WordPiece 토큰 중 약 15%를 예측 대상으로 고른다. Encoder에서 이 위치의 마지막 hidden state를 구한 뒤 Softmax 출력층으로 원래 토큰을 예측한다.
- **NSP** — 문장 쌍의 절반은 실제로 이어지는 문장으로, 나머지 절반은 두 번째 문장을 무작위로 뽑아 만든다. `[CLS]`의 마지막 hidden state를 사용해 두 문장이 이어지는지를 IsNext와 NotNext로 분류한다.

### 1.6 Masked Language Modeling

선택된 15%의 토큰을 다음 세 방식으로 처리하고, 모두 원래 토큰을 정답으로 예측한다.

- **80%** — `[MASK]`로 바꾼다.
- **10%** — 무작위 토큰으로 바꾼다.
- **10%** — 원래 토큰을 그대로 둔다.

모든 예측 대상을 `[MASK]`로 바꾸면 `[MASK]`를 거의 쓰지 않는 Fine-tuning 입력과 차이가 생긴다. 치환과 원본 유지를 섞으면 일반 토큰처럼 보이는 위치 중 어느 곳이 예측 대상인지 입력만으로 알 수 없어 각 위치의 문맥을 반영하게 된다. 전체 토큰의 약 1.5%만 무작위 토큰으로 바뀐다.

### 1.7 BERT Fine-tuning

사전학습한 BERT Encoder에 과제에 맞는 출력층을 붙이고, 레이블이 있는 과제 데이터로 Encoder와 출력층을 함께 학습한다.

| 과제 | 사용 표현과 예측값 |
|---|---|
| **문장·문장 쌍 분류** | [CLS]의 최종 hidden state를 Softmax 분류층에 입력해 문장이나 문장 쌍의 클래스 확률을 예측한다. |
| **추출형 질의응답** | 질문과 지문 세그먼트를 이어서 입력한다. 지문 토큰의 최종 hidden state를 사용해 정답의 시작과 끝에 해당할 확률을 각각 계산한다. |
| **시퀀스 태깅** | 각 토큰의 최종 hidden state를 분류층에 직접 넣어 개체명 등 토큰별 레이블을 예측한다. 이전 레이블을 차례로 입력받지 않는 비자기회귀 방식이다. 구현에 따라 CRF를 덧붙여 레이블 간 관계를 반영할 수 있다. |

### 1.8 Fine-tuning의 입력·출력 표현

BERT의 입력은 한 문장 또는 두 문장을 각각 구분할 수 있게 표현한다.

- **문장** — 문법적으로 완결된 문장에 한정하지 않고, 하나의 세그먼트로 취급하는 연속된 텍스트의 범위다.
- **시퀀스** — BERT에 넣는 전체 토큰 열이다. 한 문장이나 두 문장을 묶어서 구성한다.
- **토큰** — WordPiece로 나눈 단어 조각이나 특수 토큰이다. 예를 들어 ‘playing’은 ‘play’와 ‘##ing’으로 나눌 수 있다. 첫 토큰은 `[CLS]`이고, 각 세그먼트 끝에 `[SEP]`를 넣는다.
- **임베딩** — 각 위치에 토큰 임베딩과 위치 임베딩, 해당 토큰이 속한 세그먼트의 학습된 임베딩을 더한다.

단일 문장은 `[CLS] 문장 A [SEP]`로 구성하고 세그먼트 ID를 모두 0으로 둔다. 문장 쌍은 `[CLS] 문장 A [SEP] 문장 B [SEP]`로 구성하고 A 쪽에는 0, B 쪽에는 1을 부여한다.

### 1.9 BERT의 장점 및 성능

| 장점 | 이유 |
|---|---|
| **전이학습** | 사전학습으로 얻은 언어 표현을 재사용해 적은 양의 과제 데이터로도 학습할 수 있다. |
| **양방향 문맥** | 각 토큰을 해석할 때 양쪽 문맥을 참고해 한 단어의 의미를 문장에 맞게 파악한다. |
| **문장 수준 이해** | 문장 또는 문장 쌍의 표현으로 감성 분석, 의도 분류, 문장 관계 판단을 할 수 있다. |
| **다국어 지원** | 여러 언어로 사전학습한 BERT는 언어 간 표현을 공유해 다른 언어의 과제에 적용할 수 있다. 성능은 언어별로 달라질 수 있다. |

### 1.10 BERT의 단점 및 한계

| 한계 | 이유와 대응 |
|---|---|
| **모델 크기** | 파라미터가 많으면 저장 공간과 메모리를 많이 사용해 모바일 등 자원이 제한된 환경에 적용하기 어렵다. |
| **추론 속도** | 계산량이 커 실시간 처리가 어려울 수 있다. 경량 모델이나 하드웨어 가속을 사용할 수 있다. |
| **사전학습 데이터 의존성** | 목표 분야의 용어와 문체가 사전학습 데이터에 충분히 담기지 않으면 관련 데이터로 추가 학습할 수 있다. |
| **입력 길이 제한** | 원래 BERT의 입력은 최대 512토큰이다. 더 긴 문서를 자르거나 나누면 멀리 떨어진 내용의 관계를 놓칠 수 있다. |

## 2. GPT

### 2.1 GPT 모델이란?

**GPT** (Generative Pre-trained Transformer)는 Transformer **Decoder-only** 구조로 다음 토큰을 예측한다. 대규모 레이블 없는 텍스트에서 다음 토큰 예측으로 언어 패턴을 학습한다. 학습된 모델은 텍스트 생성, 번역, 요약 등 다양한 자연어 처리 과제에 사용할 수 있다. GPT-4는 이 계열의 후속 모델이다.

### 2.2 ELMo와 GPT 비교

ELMo는 정방향과 역방향 LSTM을 각각 학습해 양쪽 방향의 표현을 결합한다. GPT는 Decoder의 Causal Mask로 미래 위치를 가려 앞쪽 문맥만으로 다음 토큰을 예측한다.

### 2.3 GPT 모델 아키텍처

Decoder 블록은 **Masked Multi-Head Self-Attention, FFN, Layer Normalization**을 사용한다. Causal Mask로 각 위치가 뒤에 있는 토큰을 참조하지 못하게 한다. 출력층은 Decoder의 표현을 어휘 전체에 대한 다음 토큰 확률로 바꾼다.

**사전학습**에서는 원문에 실제로 이어지는 토큰을 정답으로 사용한다. 각 위치의 예측 분포와 정답 사이의 Cross-Entropy를 계산하고, 경사하강법 (Gradient descent) 계열의 최적화로 손실을 줄이는 방향으로 파라미터를 갱신한다.

### 2.4 GPT 모델의 입력·출력 표현

입력 문장이나 문단을 단어 조각·문장부호 등을 포함하는 토큰 열로 나누고, 토큰 임베딩과 위치 정보를 모델에 넣는다.

**생성**에서는 다음 토큰을 하나 선택해 입력 뒤에 붙이고, 이어진 토큰 열로 다음 예측을 반복한다. 완성된 토큰 열을 텍스트로 변환해 응답이나 문장을 얻는다. 주어진 문장을 완성하거나 질문에 답하는 작업도 이러한 방식으로 텍스트를 이어서 생성한다.

### 2.5 GPT의 장점

| 장점 | 이유와 활용 |
|---|---|
| **자연스러운 텍스트 생성** | 앞 문맥에 이어지는 문장을 만들어 글 작성·번역·요약에 활용한다. |
| **대화형 응답** | 사용자 입력과 앞선 대화를 조건으로 응답을 생성한다. |
| **빠른 프로토타이핑** | 사전학습한 언어 이해와 생성 능력으로, 추가 학습 없이도 챗봇 등 응용을 빠르게 시험할 수 있다. |

### 2.6 GPT의 성능

| 특징 | 설명 |
|---|---|
| **모델 규모 선택** | 큰 모델은 복잡한 과제에 유리할 수 있고 작은 모델도 여러 자연어 처리 작업에 쓸 수 있다. 과제 난도와 계산 자원을 고려해 규모를 선택한다. |
| **문맥 활용** | Attention으로 입력 범위 안의 떨어진 위치를 직접 참조할 수 있다. |
| **전이학습** | 사전학습한 모델을 특정 데이터와 과제에 맞게 추가 학습할 수 있다. |

### 2.7 GPT의 단점

| 단점 | 이유 |
|---|---|
| **출력 변동성** | 확률적으로 토큰을 선택하는 방법을 사용하면 같은 입력에서도 결과가 달라질 수 있다. |
| **긴 입력의 문맥 파악** | 입력 가능한 토큰 수가 제한되고, 범위 안에서도 긴 입력의 모든 관계를 정확히 반영하기 어렵다. |

### 2.8 GPT의 한계

| 한계 | 이유 |
|---|---|
| **전문 분야 특화** | 일반 텍스트 위주로 학습한 모델은 특정 분야의 전문 지식이나 용어가 부족할 수 있다. |
| **긴 대화의 지속성** | 여러 차례 대화하면서 앞선 발화나 조건이 입력에서 잘리거나 제대로 반영되지 않으면 응답의 일관성이 떨어질 수 있다. |
| **편향** | 학습 데이터에 포함된 사회적·문화적 편향이 응답에 나타날 수 있다. |

## 3. Fine-tuning

### 3.1 Fine-tuning이란?

**Fine-tuning**은 사전학습한 모델을 특정 작업에 맞는 새로운 데이터로 추가 학습하는 기술이다. 이미 학습한 표현을 새 작업에 활용하는 **전이학습** (Transfer learning)의 한 형태다. 사전학습에서 얻은 언어 표현을 활용해 적은 과제 데이터로도 여러 자연어 처리 작업에 적용할 수 있다.

### 3.2 Fine-tuning 과정

1. 과제에 맞는 사전학습 모델을 선택한다.
2. Fine-tuning에 사용할 데이터를 준비한다.
3. 데이터를 선택한 모델에 맞게 전처리한다.
4. 모델을 Fine-tuning한다.
5. 검증 데이터로 평가하고 하이퍼파라미터를 조정한다.
6. 학습한 모델을 저장한다.

목표 과제에 맞는 모델과 데이터를 고르고, 검증 데이터에서 하이퍼파라미터를 평가하는 과정이 중요하다.

### 3.3 Fine-tuning 적용 사례

| 과제 | 학습 데이터 | 학습 목표와 출력 |
|---|---|---|
| **감성 분석** | 문장과 긍정·부정 등 감성 레이블 | 감성별 점수를 내는 출력층을 붙여 감성 레이블을 예측한다. |
| **텍스트 분류** | 문서와 주제 등 클래스 레이블 | 예측 클래스 확률과 정답 레이블의 차이를 줄이도록 모델을 추가 학습한다. |
| **개체명 인식** (NER) | 텍스트와 단어·하위 단어에 대응하는 개체 레이블 | 토큰별 출력층을 붙여 사람·장소·기관명 같은 레이블을 예측한다. |
| **추출형 질의응답** | 질문·지문과 지문 속 정답 범위 | 시작·끝 위치를 예측하고, 실제 정답 위치와의 차이를 줄인다. |
| **텍스트 생성** | 목표 유형·문체의 텍스트 예시 | 예시로 추가 학습해 생성된 텍스트가 원하는 문체·톤·구조를 따르도록 한다. |

### 3.4 Fine-tuning의 장점

| 장점 | 이유 |
|---|---|
| **적은 레이블로 적응** | 사전학습한 표현이 있어 적은 수의 정답 예시로도 특정 작업을 학습할 수 있다. |
| **일반화** | 기존의 범용 표현을 새 과제에 사용하면 유사한 사례에도 적용하기 쉽다. |
| **시간과 비용 절감** | 처음부터 모델을 학습하거나 많은 레이블을 새로 수집하는 비용을 줄일 수 있다. |
| **다국어 적용** | 다국어 능력이 있는 사전학습 모델을 목표 언어의 데이터로 추가 학습할 수 있다. |

### 3.5 Fine-tuning의 단점

| 단점 | 이유 |
|---|---|
| **과적합** | 작은 훈련 집합에 지나치게 맞추면 처음 보는 사례의 성능이 떨어진다. |
| **데이터 양·품질·대표성** | 정확한 데이터를 충분히 확보하고 실제 사용 사례의 다양성을 반영해야 새 입력에 일반화할 수 있다. |
| **시간과 계산 비용** | 기반 모델이나 과제 데이터셋이 크면 Fine-tuning에도 상당한 학습 시간과 계산 자원이 필요하다. |
| **사전학습 모델 적합성** | 기반 모델이 학습한 표현이나 구조가 목표 작업에 맞지 않으면 추가 학습의 효과가 제한된다. |
| **다른 작업으로의 이전** | 한 작업에 맞춘 결과를 크게 다른 작업에 적용하려면 별도 데이터와 재학습이 필요할 수 있다. |

## 4. Interactive GPT 모델

### 4.1 Interactive GPT 모델의 소개

대화형 GPT는 사용자와 실시간으로 상호작용하며, 질의와 대화 문맥에 맞춰 응답을 생성한다. 사용자의 요구를 더 잘 반영하기 위해 사람의 평가를 수집하고, 이를 후속 모델 업데이트와 Fine-tuning에 활용해 응답을 지속적으로 개선할 수 있다.

- **실시간 상호작용** — 사용자와 자연어로 대화를 주고받는다.
- **사용자 중심** — 사용자의 요청과 앞선 대화에 맞춰 응답을 구성한다.
- **사람 피드백 활용** — 사람이 작성한 응답과 후보 비교 등의 신호를 수집한다.
- **모델 업데이트와 Fine-tuning** — 수집한 피드백으로 후속 학습과 모델 업데이트를 수행한다.
- **실시간 응답** — 대화 중 사용자의 질문에 바로 답을 생성한다.
- **지속적인 개선** — 평가와 후속 학습을 반복해 응답 품질을 개선한다.

### 4.2 Interactive GPT 모델 동작 1 — 지도 Fine-tuning (SFT)

**RLHF** (Reinforcement Learning from Human Feedback)에서는 후보 응답에 대한 사람의 선호로 보상 모델을 학습하고, 그 모델이 매긴 점수로 응답을 생성하는 정책을 개선한다.

프롬프트와 사람이 작성한 모범 응답 쌍으로 사전학습 언어 모델을 갱신한다.

### 4.3 Interactive GPT 모델 동작 2 — 보상 모델 학습

같은 프롬프트에서 만든 후보 응답을 사람이 선호 순으로 평가한다. 보상 모델은 선호되는 응답에 더 높은 점수를 주도록 학습한다.

### 4.4 Interactive GPT 모델 동작 3 — 정책 최적화

SFT 모델의 파라미터로 정책 모델을 초기화한다. 정책 모델이 새 프롬프트에 응답하면 보상 모델이 점수를 매긴다. PPO (Proximal Policy Optimization)로 높은 보상을 받는 방향으로 정책 모델을 갱신한다.

### 4.5 Interactive GPT 모델의 응용

| 응용 | 활용 |
|---|---|
| **고객 지원 챗봇** | 자연어 문의에서 사용자의 상황을 파악하고 해결책을 안내한다. 반복되는 문의에 상시 대응할 수 있다. |
| **가상 도우미** | 대화로 정보를 제공하고 일정이나 알림, 웹 검색, 스마트홈 제어 등을 지원한다. |
| **콘텐츠 제작과 아이디어 제안** | 기사·마케팅 자료·대본의 초안을 작성하거나 창작 아이디어를 제시한다. |
| **언어 번역과 학습** | 대화를 번역하고 문맥·어휘 설명과 대화 연습을 제공한다. |

### 4.6 Interactive GPT 모델의 잠재력과 가능성

- **대화와 의사소통 개선** — 자연스럽고 의미 있는 대화를 통해 고객 지원, 상담, 교육에서 의사소통을 돕는다.
- **실시간 정보와 지원 제공** — 사용자가 질문하는 시점에 바로 설명이나 안내를 제공한다.
- **콘텐츠 생성과 창작 지원** — 글쓰기, 시나리오, 가사 쓰기 등에서 아이디어나 초안을 제안한다.
- **교육과 자기 학습** — 학습자의 질문에 답하고 이해 수준과 요청에 맞는 설명을 제공한다.

### 4.7 실제 예시 — ChatGPT

대화 문맥을 이어가며 고객 지원, 콘텐츠 작성, 아이디어 발상에 활용할 수 있다. 예를 들어 콘텐츠 제작 사업 아이디어를 요청하면 가상 행사 기획과 같은 사업안을 제안하고 제공할 서비스를 구체화한다.

### 4.8 실제 예시 — Replika

가상의 친구나 동반자와 대화하는 챗봇이다. 대화 문맥을 추적해 공감하는 응답과 개인화된 대화를 제공한다.

### 4.9 실제 예시 — AI Dungeon

텍스트 기반 어드벤처 게임이다. 플레이어가 행동을 텍스트로 입력하면 모델이 그에 맞게 이야기를 이어 가고, 플레이어는 다음 행동으로 전개를 바꿀 수 있다.

## 5. 사람 피드백 학습

### 5.1 사람 피드백 학습의 정의와 개념

사람 피드백 학습은 사용자의 지시·평가·교정이나 전문가의 주석을 학습에 반영해 모델을 개선하는 방식이다.

사전학습 → 피드백 수집 → 모델 업데이트·Fine-tuning → 평가·검증

### 5.2 사람의 피드백 이해

사람 전문가나 사용자는 모델에 입력·안내·평가를 제공한다. 이러한 신호는 모델이 여러 과제를 이해하고 적응하는 데 도움이 된다.

| 피드백 | 예 |
|---|---|
| **명시적** | 사용자가 직접 제공하는 레이블·주석, 답변 수정, 응답 점수나 선호 순위다. 예를 들어 이미지에 객체 레이블을 붙이거나 생성 문장을 교정한다. |
| **암묵적** | 클릭, 체류 시간, 반복 선택 등 사용 행동에서 얻는 신호다. 이런 행동 패턴을 추천과 개인화 개선에 활용할 수 있다. |

### 5.3 학습 종류와 예시

| 학습 방식 | 피드백의 쓰임 |
|---|---|
| **지도학습** | 사람이 제공한 정답이나 레이블을 목표로 학습한다. 예를 들어 메일을 스팸·정상으로 표시해 분류 모델을 학습시킨다. |
| **강화학습** | 환경에 행동을 취하고 그 결과로 얻는 보상을 높이도록 학습한다. 예를 들어 자율주행에서는 여러 주행 상황에서 어떤 행동을 선택할지 학습할 수 있다. RLHF에서는 사람 선호로 학습한 보상 모델의 점수를 사용한다. |
| **대화형 학습** | 상호작용에서 얻은 평가와 교정을 후속 학습에 반영한다. 예를 들어 사용자가 챗봇의 답변을 수정한 기록을 활용한다. |

### 5.4 AI 학습에서 사람 피드백의 역할

- **모델 최적화 유도** — 주석·수정·선호 순위는 원하는 결과에 맞춰 모델의 파라미터를 갱신하는 신호가 된다. 암묵적 피드백은 예측과 행동을 개선하는 데 사용할 수 있다.
- **정보에 근거한 의사결정** — 적절한 응답과 부적절한 응답의 사례를 함께 제공하면, 복잡한 상황에서 어떤 응답이나 행동이 문맥과 사용자 의도에 맞는지 학습하는 데 도움이 된다.

### 5.5 사람 피드백 학습의 문제점

| 한계 | 이유와 대응 |
|---|---|
| **편향** | 평가 집단의 사회적·문화적 편향이 모델에 반영될 수 있다. 다양한 집단의 의견을 수집한다. |
| **확장성** | 사용량과 과제가 늘면 서로 다른 상황에서 대량의 피드백을 일관되게 수집·처리·통합하기 어려워진다. |
| **주관성과 다양성** | 평가자마다 선호가 다를 수 있다. 공통 지침으로 일관성을 높이면서 다양한 의견을 반영한다. |
| **수집과 검증** | 피드백의 대표성과 관련성을 검증하고 주석 오류를 점검해야 한다. |

### 5.6 사람 피드백 사이클

1. **모델과의 상호작용** — 모델이 사용자 입력이나 과제에 대한 출력을 생성한다.
2. **피드백 입력** — 사람은 평가·수정처럼 직접 피드백을 주거나, 행동을 통해 간접 신호를 제공한다.
3. **피드백 반영** — 피드백을 학습에 사용해 파라미터와 응답을 결정하는 방식을 조정한다.
4. **모델 개선** — 갱신한 모델은 피드백을 반영해 문맥과 사용자 요구에 더 적합한 출력을 생성하도록 개선한다.
5. **지속 학습** — 새 모델에 대한 피드백을 다시 수집해 이 사이클을 반복한다.

### 5.7 사람 피드백 학습의 구현

1. **데이터 수집** — 실제 대화, 사용자 행동, 전문가 의견에서 학습과 검증에 필요한 자료를 수집한다.
2. **주석 달기** — 사람이 레이블·수정안·점수 등을 붙이고, 일관성과 대표성을 점검한다.
3. **모델 업데이트** — 주석이나 평가를 반영해 모델을 Fine-tuning한다. 이후 새 응답이 개선됐는지 평가한다.

### 5.8 사람 피드백 학습의 장점

| 장점 | 이유 |
|---|---|
| **성능 개선** | 사람이 제공한 정답·수정·선호는 정확성과 관련성을 높이는 학습 신호가 된다. |
| **적응성 향상** | 새 요구나 오류에 대한 피드백을 다시 반영해 모델을 개선할 수 있다. |
| **편향 완화** | 여러 관점의 피드백으로 특정 집단에 불공정한 결과를 발견하고 줄일 수 있다. |
| **다양한 업무 처리** | 여러 종류의 과제와 실패 사례에서 받은 피드백으로 대응할 수 있는 상황을 넓힌다. |

### 5.9 실제 적용 사례

| 분야 | 피드백을 반영하는 방식 |
|---|---|
| **언어 번역** | Google 번역과 같은 시스템에서 사람이 교정한 표현을 반영하면 번역의 정확도와 문맥에 맞는 표현을 개선하는 데 도움이 된다. |
| **콘텐츠 생성** | GPT-3 계열의 생성 시스템에서는 글의 문체·일관성·관련성에 대한 사람의 평가와 수정 예시를 반영할 수 있다. 글쓰기와 마케팅, 창작에 사용하는 결과를 개선하는 데 활용한다. |
| **로봇 공학** | 사람이 동작을 안내하고 교정한 사례를 이용해 환경 탐색과 작업 수행을 학습한다. |
| **의료 영상 분석** | 전문가가 영상의 소견이나 모델의 판단을 검토한 결과를 반영해 분석 성능을 개선한다. |

## 6. GPT 환각 — 기출 보충

**환각** (Hallucination)은 그럴듯하면서도 사실이나 주어진 근거와 맞지 않는 내용을 생성하는 현상이다. 불확실한 질의가 주어지면 GPT가 추측해서 답하거나 부정확한 내용을 생성할 수 있다.

**보충** · 환각의 원인별 대응

| 원인 | 기술적 완화 |
|---|---|
| **학습 목표와 사실성의 차이**. 다음 토큰을 예측하는 학습만으로 사실을 검증하지는 않는다. | 검증된 데이터와 피드백으로 Fine-tuning하고, 생성된 주장을 검색·계산·DB 같은 외부 도구로 대조한다. |
| **지식의 부족이나 오류**. 학습 데이터에 잘못된 정보가 섞이거나 최신·전문 지식이 부족할 수 있다. | **RAG** (Retrieval-Augmented Generation)로 관련 문서를 검색하고 근거를 프롬프트에 넣어 답을 생성한다. 검색 자료가 질문에 맞는지도 확인한다. |
| **모호한 입력과 불충분한 문맥**. 전제가 불명확하거나 필요한 근거가 없으면 모델이 빈 부분을 추측할 수 있다. | 필요한 조건과 맥락을 명시하고, 근거가 부족하면 추가 질문을 하거나 응답을 보류하게 한다. |
| **오류 누적**. 자기회귀 생성은 이미 출력한 내용을 다음 문맥으로 사용한다. | 중간 또는 최종 주장을 원문과 대조해 잘못된 전제가 후속 답변으로 이어지는 것을 줄인다. |

**RAG**는 응답 시 입력에 근거를 추가한다. **Fine-tuning**은 학습으로 모델의 파라미터를 갱신한다.
