## 1. BERT 모델
### 1.1 BERT의 구조와 입력 표현
**BERT** (Bidirectional Encoder Representations from Transformers)는 **양방향 Transformer Encoder**를 사용해 대규모 말뭉치에서 앞뒤 문맥을 함께 반영하는 언어 표현을 사전학습한 뒤, 분류·질의응답 등 다운스트림 과제에 적용하는 모델이다.
- **문장·시퀀스·토큰** — 문장은 연속된 텍스트 구간이며, 시퀀스는 단일 문장이나 두 문장으로 구성된 입력 토큰 열이다. 토큰은 **WordPiece** 하위 단어 (`playing` → `play`, `##ing`)와 특수 토큰으로 이루어지며, 첫 토큰은 `[CLS]`, 각 세그먼트 끝에는 `[SEP]`를 붙인다.

| 입력 | 토큰 배열 | 세그먼트 ID |
|---|---|---|
| **단일 문장** | `[CLS] 문장 A [SEP]` | 모두 0 |
| **문장 쌍** | `[CLS] 문장 A [SEP] 문장 B [SEP]` | 첫 구간은 0, 두 번째 구간은 1 |
각 위치의 입력 벡터는 아래 세 임베딩을 더한 값이다.

| 임베딩 | 역할 |
|---|---|
| **Token embedding** | WordPiece나 특수 토큰을 벡터로 표현한다. |
| **Segment embedding** | 같은 세그먼트에 속한 토큰에 동일한 학습 벡터를 더해 문장 A·B를 구분한다. |
| **Position embedding** | 토큰의 위치를 나타낸다. 원래 Transformer의 삼각함수와 달리 학습 가능한 벡터를 사용한다. |
### 1.2 BERT의 사전학습 (Pre-training)
레이블 없는 텍스트에서 두 과제를 함께 학습한다.

| 과제 | 입력과 학습 목표 |
|---|---|
| **MLM** (Masked Language Modeling) | 일부 토큰을 가리거나 바꾼 입력을 주고, 해당 위치의 최종 hidden state와 Softmax 출력층으로 앞뒤 문맥에서 원래 토큰을 예측한다. |
| **NSP** (Next Sentence Prediction) | 문장 쌍의 절반은 실제 이어지는 문장, 나머지는 무작위 문장으로 구성해 `[CLS]`의 최종 hidden state로 IsNext와 NotNext를 분류한다. |
- **MLM 80 / 10 / 10 전략** — 전체 토큰의 **약 15%**를 예측 대상으로 고른 뒤 **80%**는 `[MASK]`, **10%**는 무작위 토큰, **10%**는 원래 토큰 그대로 두고 모두 원래 토큰을 정답으로 예측한다. Fine-tuning과의 입력 차이를 줄이고, Encoder가 어느 위치가 예측 대상인지 알 수 없어 모든 위치의 문맥을 반영하도록 유도한다 (전체 중 무작위 치환은 약 1.5%).
### 1.3 BERT의 Fine-tuning
사전학습한 Encoder에 과제별 출력층을 붙이고 레이블이 있는 데이터로 Encoder와 출력층을 함께 학습한다. 문장·문장 쌍 분류는 `[CLS]` 최종 표현을, 개체명 인식 (NER)은 각 토큰의 최종 표현을, 추출형 질의응답은 지문 토큰 표현으로 정답 시작·끝 위치를 예측한다 ([[#3.2 Fine-tuning 적용 사례|적용 사례 상세]]).
### 1.4 BERT의 장점과 한계

| 장점 | 이유 |
|---|---|
| **전이학습** | 사전학습 언어 표현을 재사용해 적은 과제 데이터로도 높은 성능을 얻는다. |
| **양방향 문맥** | 좌우 문맥을 함께 참고해 단어 의미를 문장에 맞게 파악한다. |
| **문장 수준 이해** | 단일·문장 쌍 표현으로 감성 분석, 의도 분류, 문장 관계 판단에 유리하다. |
| **다국어 지원** | 다국어 사전학습으로 언어 간 표현을 공유해 다른 언어 과제에 적용한다. |

| 한계 | 이유와 대응 |
|---|---|
| **모델 크기·추론 속도** | 파라미터가 많아 메모리와 계산량이 크고 실시간 처리가 느릴 수 있다 (경량 모델·하드웨어 가속 활용). |
| **사전학습 데이터 의존성** | 목표 분야의 전문 용어·문체가 부족하면 관련 데이터로 추가 학습해야 한다. |
| **입력 길이 제한** | 원래 BERT 입력은 최대 **512토큰**으로, 긴 문서를 자르거나 나누면 멀리 떨어진 내용 관계를 놓칠 수 있다. |
## 2. GPT
### 2.1 구조와 사전학습·생성
**GPT** (Generative Pre-trained Transformer)는 **Decoder-only** 구조의 단방향 언어 모델이다. 입력 텍스트를 토큰으로 나누어 토큰 임베딩과 위치 정보를 더하고, **Masked Multi-Head Self-Attention** (Causal mask로 미래 토큰 차단), FFN, LayerNorm으로 구성된 Decoder 블록을 거쳐 다음 토큰 확률을 출력한다.

| 과정 | 동작 방식 |
|---|---|
| **사전학습** | 실제로 이어지는 다음 토큰을 정답으로 삼아 예측 분포와 정답의 **Cross-Entropy** 손실을 줄이도록 파라미터를 갱신한다. |
| **생성** | 입력에 이어질 토큰을 하나 선택해 뒤에 붙이고, 확장된 토큰 열을 다시 입력해 다음 토큰을 예측하는 자기회귀 방식으로 텍스트를 완성한다. |
### 2.2 GPT의 장점과 한계

| 장점 | 이유와 활용 |
|---|---|
| **자연스러운 생성·대화** | 앞 문맥에 이어지는 텍스트를 만들어 글 작성·번역·요약·대화형 챗봇에 활용한다. |
| **빠른 프로토타이핑** | 사전학습 언어 이해·생성 능력으로 추가 학습 없이도 응용을 빠르게 시험한다. |
| **문맥 활용·규모 선택** | Attention으로 입력 범위 내 떨어진 위치를 직접 참조하며, 과제 난도와 자원에 맞춰 모델 규모를 선택한다. |
| **전이학습** | 사전학습 모델을 특정 도메인 데이터와 과제에 맞게 추가 학습할 수 있다. |

| 한계 | 이유 |
|---|---|
| **출력 변동성** | 확률적 토큰 샘플링을 쓰면 같은 입력에서도 결과가 달라져 일관성이 떨어질 수 있다. |
| **긴 입력·대화 지속성** | 입력 토큰 수가 제한되고, 긴 대화에서 앞선 발화나 조건이 잘리면 문맥 일관성이 저하된다. |
| **전문 분야 특화 한계** | 일반 텍스트 위주로 학습한 모델은 특정 비즈니스·전문 분야 지식이 부족할 수 있다. |
| **편향** | 학습 데이터에 포함된 사회적·문화적 편향이 응답에 반영될 수 있다. |
### 2.3 BERT·GPT·ELMo 비교

| 모델 | 구조와 문맥 사용 | 사전학습에서 예측하는 것 |
|---|---|---|
| **BERT** | 양방향 Transformer Encoder로 좌우 문맥을 함께 본다. | 가려지거나 바뀐 위치의 원래 토큰 (MLM)과 두 문장의 연속 여부 (NSP)를 예측한다. |
| **GPT** | Transformer Decoder와 Causal mask로 앞쪽 문맥만 본다. | 실제로 이어지는 다음 토큰을 예측한다. |
| **ELMo** | 2층 LSTM으로 정방향과 역방향 언어 모델을 따로 학습하고 두 표현을 결합한다. | 각 방향에서 주어진 문맥에 이어지는 토큰을 예측한다. |
## 3. Fine-tuning
### 3.1 정의와 과정
사전학습한 모델을 특정 과제에 맞는 새 데이터로 추가 학습하는 **전이학습** 방식이다.
**사전학습 모델 선택 → 과제 데이터 준비 → 입력 형식 전처리 → 모델 Fine-tuning → 검증·하이퍼파라미터 튜닝 → 모델 저장**
### 3.2 Fine-tuning 적용 사례

| 과제 | 학습 데이터 | 사용하는 표현과 출력 |
|---|---|---|
| **감성 분석** | 문장과 긍정·부정 감성 레이블 | BERT에서 `[CLS]` 최종 표현을 Softmax 분류층에 넣어 감성 확률을 예측한다. |
| **텍스트 분류** | 문장·문서·문장 쌍과 과제 레이블 | BERT에서 `[CLS]` 최종 표현을 분류층에 넣어 주제나 문장 관계를 예측한다. |
| **개체명 인식** (NER) | 토큰별 인명·장소·기관 레이블 | 각 토큰의 최종 표현으로 레이블을 예측한다 (비자기회귀, 구현에 따라 CRF 결합). |
| **추출형 질의응답** (QA) | 질문·지문과 지문 속 정답 범위 | 질문과 지문을 한 시퀀스로 넣고, 지문 토큰 표현으로 정답의 시작·끝 위치를 각각 예측한다. |
| **텍스트 생성** | 원하는 문체·톤·구조의 텍스트 예시 | GPT 같은 생성 모델을 추가 학습해 목표 속성의 텍스트를 출력한다. |
### 3.3 Fine-tuning의 장점과 단점

| 장점 | 이유 |
|---|---|
| **적은 레이블·비용 절감** | 사전학습 표현을 재사용해 적은 정답 데이터와 짧은 시간·비용으로 과제에 적응한다. |
| **일반화·다국어 적용** | 범용 언어 표현을 활용해 유사 사례에 잘 일반화되며, 다국어 모델을 목표 언어에 확장할 수 있다. |

| 단점 | 이유 |
|---|---|
| **과적합** | 작은 훈련 집합에 지나치게 맞추면 처음 보는 데이터에서 성능이 떨어진다. |
| **데이터 품질·대표성 의존** | 정확한 데이터와 실제 사례의 다양성을 확보하지 못하면 일반화가 어렵다. |
| **계산 비용·모델 적합성** | 기반 모델이 크면 추가 학습 비용이 크고, 목표 과제와 맞지 않으면 효과가 제한되며 타 작업 이전 시 재학습이 필요하다. |
## 4. Interactive GPT
### 4.1 RLHF 학습 과정
대화형 GPT는 사용자 요청과 이전 대화에 맞춰 응답하며, **RLHF** (Reinforcement Learning from Human Feedback)로 사람 선호를 반영한 보상 모델 점수를 이용해 정책을 개선한다.
**지도 Fine-tuning** (SFT) → **보상 모델 학습** (RM) → **정책 최적화** (PPO)

| 단계 | 사용하는 데이터 | 갱신하는 모델 |
|---|---|---|
| **지도 Fine-tuning** (SFT) | 프롬프트와 사람이 작성한 모범 응답 쌍 | 사전학습 언어 모델을 모범 응답에 맞게 학습한다. |
| **보상 모델 학습** (RM) | 같은 프롬프트의 후보 답변들과 사람이 매긴 선호 순위 | 사람이 선호한 응답에 더 높은 점수를 주도록 보상 모델을 학습한다. |
| **정책 최적화** (PPO) | 새 프롬프트, 정책 모델 응답, 보상 모델 점수 | SFT로 초기화한 정책 모델을 **PPO** (Proximal Policy Optimization)로 갱신해 높은 보상을 얻도록 한다. |
- **주요 응용과 사례** — 고객 지원·상담, 가상 도우미, 콘텐츠 제작, 번역·언어 학습, 교육에 활용한다 (예: ChatGPT, 공감형 대화 챗봇 Replika, 텍스트 어드벤처 AI Dungeon).
## 5. 사람 피드백 학습
### 5.1 피드백 유형과 학습 반영
사용자의 지시·평가·교정이나 전문가 주석을 반영해 모델을 지속적으로 개선하는 방식이다.
**응답 생성 → 피드백 수집 → 주석·검증 → 모델 갱신 → 평가 반복**

| 피드백 유형 | 신호 출처와 예시 |
|---|---|
| **명시적 피드백** | 사람이 직접 제공한 레이블·평가·수정·선호 순위 (객체 레이블링, 생성 문장 교정, 응답 순위). |
| **암묵적 피드백** | 사용자 행동에서 추정한 신호 (클릭, 체류 시간, 반복 선택을 통한 추천·개인화 개선). |
- **반영 방식** — **지도학습** (정답 레이블 학습, 예: 스팸 분류), **강화학습** (보상 최대화, 예: RLHF·자율주행), **대화형 학습** (상호작용 중 수정 기록을 후속 학습에 반영) 등을 사용한다.
### 5.2 장점과 한계
- **장점과 적용** — 성능 개선, 새 오류에 대한 적응성, 편향 완화, 다양한 업무 대응에 유리하며 번역·콘텐츠 생성·로봇 공학·의료 영상 분석에 적용한다.

| 한계 | 이유와 대응 |
|---|---|
| **편향** | 평가 집단의 사회적·문화적 편향이 모델에 전파될 수 있어 다양한 집단의 의견을 수집한다. |
| **확장성** | 사용량과 과제가 늘면 대량의 피드백을 일관되게 수집·처리·통합하기 어려워진다. |
| **주관성과 다양성** | 평가자마다 선호가 다르므로 공통 지침으로 일관성을 높이면서 다양성을 균형 있게 반영한다. |
| **수집과 검증** | 피드백의 대표성과 품질을 검증하고 주석 오류를 점검해야 한다. |
## 6. GPT 환각 — 기출 보충
**환각** (Hallucination)은 사실이나 주어진 근거와 맞지 않는 내용을 그럴듯하게 생성하는 현상이다.

| 원인 | 기술적 완화 방법 |
|---|---|
| **다음 토큰 예측과 사실 검증의 괴리** — 문맥상 확률이 높은 토큰을 이어 붙이다 근거 없는 주장을 생성한다. | 검증된 데이터와 **RLHF**로 Fine-tuning하고, 생성한 주장을 외부 검색·계산기·DB와 대조 검증한다. |
| **학습 데이터 오류·지식 부족** — 잘못된 정보가 포함됐거나 최신·전문 지식이 부족하다. | **RAG** (Retrieval-Augmented Generation)로 관련 신뢰 문서를 검색해 프롬프트 근거로 주입한다. |
| **모호한 질문·문맥 부족** — 필요한 전제나 근거가 없으면 빈 부분을 추측해 채운다. | 명확한 조건·문맥을 제공하고, 근거가 부족할 때 추가 질문하거나 답변을 보류하도록 유도한다. |
| **자기회귀 생성의 오류 누적** — 잘못 생성된 앞 토큰이 다음 예측 문맥에 들어가 오류가 증폭된다. | 중간·최종 주장을 원문 근거와 대조해 잘못된 전제를 탐지하고 교정한다. |
- **RAG vs Fine-tuning** — **RAG**는 응답 생성 시 외부 검색 근거를 입력 프롬프트에 추가해 최신성·근거성을 높이고, **Fine-tuning**은 추가 학습으로 모델의 파라미터 자체를 갱신한다.
