# 1. 윈도우 시스템 부팅 프로세스
## 1.1 기본 부팅 흐름
```text
전원 인가 → BIOS/UEFI 실행 → MBR 확인 → Boot Code 실행
→ VBR 호출 → OS 이미지 적재 → 커널 실행 → 초기화 프로세스
→ Login Prompt
```

| 단계 | 핵심 |
| --- | --- |
| 전원 인가 | CPU가 0번지 데이터를 읽고 **BIOS** 실행 준비 |
| **BIOS/UEFI** | POST, 하드웨어 점검, CPU/메모리/보조기억장치 초기화 |
| **MBR** | 저장매체 첫 512B, 운영체제 위치 정보 확인 |
| **Boot Code** / **VBR** | 운영체제 로딩 준비 |
| **OS/Kernel** | 운영체제 이미지 적재, 커널 실행, 시스템/장치 초기화 |
| **Login Prompt** | 사용자 인증 후 시스템 사용 가능 |
## 1.2 BIOS와 UEFI
| 구분 | **BIOS** | **UEFI** |
| --- | --- | --- |
| 성격 | 전통적 펌웨어 | **BIOS**의 차세대 펌웨어 |
| 인터페이스 | 텍스트 기반 | GUI 기반 |
| 특징 | 하드웨어 초기화 후 부트로더 실행 | 대용량 디스크 지원, 부팅 속도 개선 |
| 보안 | 제한적 | **Secure Boot** 등 부팅 이미지 무결성 검증 |
- 공통점: 둘 다 운영체제 구동 전 하드웨어 초기화와 부팅 준비를 담당한다.
## 1.3 BIOS의 포렌식 의미
**BIOS**는 운영체제보다 먼저 실행되므로 시스템 기준 정보와 부팅 환경을 확인하는 단서가 된다.

| 확인 대상 | 포렌식 의미 |
| --- | --- |
| 시스템 시계 | 기준 시간 조작 여부 확인 |
| 저장 매체 구성 | HDD/SSD 장착 여부, 용량, 구성 확인 |
| 부팅 우선순위 | 어떤 장치에서 운영체제를 불러왔는지 추정 |
| 부팅 모드 | **BIOS/UEFI**, Legacy/**Secure Boot** 환경 확인 |
- **BIOS** 정보는 운영체제 내부 기록과 **교차 검증**할 때 기준 정보로 활용할 수 있다.
# 2. 레지스트리 분석
## 2.1 윈도우 부팅 단계
| 단계 | 역할 | 포렌식 포인트 |
| --- | --- | --- |
| **Boot Manager** | **BIOS/UEFI**에서 제어권을 받아 **BCD** 로딩 | 운영체제/부팅 모드 확인 |
| **Winload.exe** / **Winload.efi** | 커널, HAL, 핵심 드라이버 메모리 로딩 | 안전모드/복구 모드 설정 확인 |
| **Kernel Init** | 커널과 서브시스템 초기화 | OS 제어권 전환 |
| **Session Manager** `smss.exe` | 사용자 세션 생성, **레지스트리** 초기화, 시작 프로그램 로딩 | 세션/자동 실행 흔적 |
| **Windows Logon** / **Explorer** | 로그인 후 사용자 환경과 데스크탑 초기화 | 이벤트 로그, **레지스트리**, 로그온 흔적 |
핵심 확인 대상:
```text
BCD + Winload + 이벤트 로그 + 레지스트리 + 세션 정보
```
## 2.2 레지스트리 기본 구조
- **레지스트리**는 윈도우의 설정 데이터베이스이며 부팅, 하드웨어, 시스템 설정, 사용자 환경 정보를 저장한다.
- 기본 계층:
```text
Hive → Key → Value
```

| 단위 | 의미 |
| --- | --- |
| **Hive** | **레지스트리**의 물리적 저장 단위 |
| **Key** | 하이브 내부의 폴더/경로 같은 구조 |
| **Value** | 실제 설정값 또는 데이터 |
## 2.3 주요 논리 키와 실제 Hive 파일
| 논리 키 | 실제 **Hive** 파일 / 위치 |
| --- | --- |
| `HKLM\SYSTEM` | `C:\Windows\System32\Config\SYSTEM` |
| `HKLM\SOFTWARE` | `C:\Windows\System32\Config\SOFTWARE` |
| `HKLM\SAM` | `C:\Windows\System32\Config\SAM` |
| `HKLM\SECURITY` | `C:\Windows\System32\Config\SECURITY` |
| `HKU\.DEFAULT` | `C:\Windows\System32\Config\DEFAULT` |
| `HKCU` | 현재 로그인 사용자의 `C:\Users\<사용자명>\NTUSER.DAT` |
| `HKU\<SID>` | 각 사용자 프로필의 `NTUSER.DAT` |
| `HKCR` | `HKLM\SOFTWARE\Classes`와 `HKCU\Software\Classes`의 병합 뷰 |
| `HKCC` | `HKLM\SYSTEM\CurrentControlSet\Hardware Profiles\Current`의 별칭 |
주의:
- `HKCU`는 독립 **Hive** 파일이 아니라 현재 로그인 사용자의 `NTUSER.DAT`를 가리키는 논리 키이다.
- `HKCR`, `HKCC`는 별도 **Hive** 파일이라기보다 기존 경로를 병합하거나 가리키는 논리 뷰이다.
## 2.4 주요 Hive / 키
| **Hive** / 키 | 저장 정보 | 포렌식 활용 |
| --- | --- | --- |
| `HKLM` | 시스템, 하드웨어, 드라이버, 서비스 정보 | 시스템 설정과 장치 구성 확인 |
| `HKCU` | 현재 로그인 사용자 환경 설정 | 사용자별 행위 흔적 확인 |
| `HKU` | 사용자 계정별 프로파일 | 여러 사용자 계정 흔적 확인 |
| `HKCR` | 파일 확장자와 프로그램 연결 정보 | 특정 파일 형식과 실행 프로그램 연결 확인 |
| `HKCC` | 현재 하드웨어 프로필 | 현재 부팅 환경의 하드웨어 구성 확인 |
# 3. 사용자 행위 아티팩트와 웹 브라우저 분석
## 3.1 레지스트리 기반 사용자 행위 흔적
### 3.1.1 프로그램 실행 / 자동 실행
| 아티팩트 | 경로 | 확인 내용 |
| --- | --- | --- |
| **UserAssist** | `HKCU\...\Explorer\UserAssist` | ROT13 인코딩된 프로그램 목록, 실행 횟수, 마지막 실행 시간 |
| 사용자별 **Run** | `HKCU\...\Run` | 현재 사용자 기준 자동 실행 항목 |
| 전체 사용자 **Run** | `HKLM\...\Run` | 시스템 전체 사용자 공통 자동 실행 항목 |
- `Run` 키는 자동 실행 설정을 보여줄 뿐 실제 실행을 직접 증명하지는 않는다.
- 악성코드는 지속 실행을 위해 `Run` 키를 자주 악용하므로 **UserAssist**, Prefetch 등과 **교차 검증**한다.
### 3.1.2 문서/파일 접근
| 아티팩트 | 경로 / 저장 정보 | 확인 내용 |
| --- | --- | --- |
| **RecentDocs** | `HKCU\...\Explorer\RecentDocs` | 최근 열었던 문서/파일, `LastWriteTime` 기반 근사 접근 시각 |
| **OpenSavePidlMRU** / **LastVisitedPidlMRU** | 문서 열기/저장 시 사용한 실제 경로 | 어떤 문서를 어떤 경로에서 접근했는지 추적 |
### 3.1.3 폴더 접근
| 아티팩트 | 경로 | 확인 내용 |
| --- | --- | --- |
| **BagMRU** | `HKCU\Software\Microsoft\Windows\Shell\BagMRU` | 폴더 열람 이력, 폴더 뷰 설정, 삭제 폴더/USB 내부 폴더 접근 흔적 |
| **TypedPaths** | `HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\TypedPaths` | 탐색기 주소창에 사용자가 직접 입력한 경로 |
- **BagMRU**는 폴더 접근 이력의 블랙박스처럼 활용된다.
- **TypedPaths**는 의도적 경로 접근 여부 판단에 도움을 준다.
### 3.1.4 USB 연결
| 아티팩트 | 경로 | 확인 내용 | 결합 분석 |
| --- | --- | --- | --- |
| **USBSTOR** | `HKLM\SYSTEM\CurrentControlSet\Enum\USBSTOR` | USB 장치명, 제조사, 시리얼 번호, 과거 연결 장치 | 외부 저장장치 사용 여부 |
| **MountedDevices** | `HKLM\SYSTEM\MountedDevices` | 장치가 어떤 드라이브 문자로 연결되었는지 확인 | 특정 USB의 마운트 경로 추적 |
**USBSTOR**, **MountedDevices**, USB 내부 폴더 접근 기록을 결합하면 파일 유출 정황을 분석할 수 있다.
## 3.2 웹 브라우저 아티팩트
| 아티팩트 | 저장/확인 내용 | 포렌식 활용 |
| --- | --- | --- |
| **방문 기록** | Chrome/Edge 등 SQLite DB, URL, 검색어, 마이크로초 단위 시간 | 타임라인 복원 |
| **캐시** | HTML, 이미지, JavaScript, 폰트 등 웹 리소스 | 히스토리 삭제 후에도 방문 사실 확인 가능 |
| **다운로드 기록** | 다운로드 파일명, 저장 위치, 다운로드 시간 | 사용자가 내려받은 파일 추적 |
| **쿠키** | 세션 유지, 자동 로그인 관련 정보 | 브라우징 패턴, 접속 시점 추정 |
| **로그인/자동완성** | 계정 정보, 이름, 주소, 이메일 등 | 계정 사용 흔적과 접속 행위 분석 |
## 3.3 교차 검증
- 단일 아티팩트만으로 행위를 단정하면 위험하다.
- **UserAssist**, Prefetch, 브라우저 DB, **캐시**, **다운로드 기록**, USB 연결 기록 등을 함께 비교해야 한다.
