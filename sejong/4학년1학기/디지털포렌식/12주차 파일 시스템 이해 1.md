# 1. 파일시스템 이해 ①
## 1.1 디스크 파티션
- **파티션**은 하나의 물리 디스크를 여러 논리 영역으로 나누는 단위이다.
- 기본 구조:
```text
디스크 → 파티션 → 파일시스템 → 파일/디렉토리 구조
```
- **파티션**을 나누면 운영체제, 데이터, 백업 영역을 분리해 관리할 수 있다.
- Windows의 `하드 디스크 파티션 만들기 및 포맷` 같은 관리 도구는 **MBR**/**GPT** **파티션** 정보를 읽어 표시한다.
## 1.2 MBR vs GPT

### 1.2.2 GPT
![[Pasted image 20260613172547.png|500]]

| 구분     | **MBR**                   | **GPT**                    |
| ------ | --------------------- | ---------------------- |
| 약자     | `Master Boot Record`  | `GUID Partition Table` |
| 위치/구조  | 디스크 첫 512B에 **파티션** 정보 저장 | 디스크 앞/뒤에 **파티션** 정보 저장     |
| 부팅 환경  | 전통적 BIOS 환경           | UEFI 기반                |
| 식별 방식  | **파티션** 테이블 엔트리           | GUID로 **파티션** 고유 식별        |
| 용량 한계  | 최대 2TB                | 최대 9.4ZB               |
| **파티션** 수  | 기본 4개                 | 사실상 제한 적음              |
| 무결성/복구 | 앞부분 손상 시 복구 어려움       | CRC, 백업 **파티션** 테이블 지원     |
### 1.2.3 MBR 구조
**MBR**은 512B이며, 다음 세 영역으로 나뉜다.

| 영역 | 크기 | 핵심 |
| --- | --- | --- |
| **Boot Code** | 446B | 부팅 시 실행되는 코드 |
| **Partition Table Entry** | 64B | 16B 엔트리 4개, **파티션** 위치와 속성 저장 |
| **Signature** | 2B | **MBR** 식별값 `0x55AA` |
### 1.2.4 MBR 파티션 엔트리
| 항목             | 핵심값 / 의미                         |
| -------------- | -------------------------------- |
| **Boot Flag**      | `0x80` 부팅 가능, `0x00` 부팅 불가       |
| **Partition Type** | NTFS `0x07`, **FAT** `0x0B`/`0x0C` 등 |
| **CHS**            | Cylinder·Head·**Sector** 기반 시작/끝 주소  |
| **LBA**            | 선형 주소 방식의 시작 위치                  |
| **Sector Count**   | **파티션** 전체 크기                        |
## 1.3 파일시스템과 메타데이터
### 1.3.1 파일시스템 역할
- **파일시스템**은 **파티션** 위에서 데이터 저장, 읽기, 탐색, 메타데이터 관리를 담당한다.
- 파일 탐색기는 **파일시스템**에 디렉토리/파일 목록을 요청하고, **파일시스템**은 메타데이터를 운영체제에 전달한다.
### 1.3.2 Data Area vs Meta Area
| 영역        | 저장 내용                        | 포렌식 의미                 |
| --------- | ---------------------------- | ---------------------- |
| **Data Area** | 실제 파일 내용                     | 삭제 후에도 데이터 조각이 남을 수 있음 |
| **Meta Area** | 파일명, 크기, 생성/수정/접근 시간 등 속성 정보 | 파일 존재와 행위 시점 추적        |
# 2. 파일시스템 이해 ②
## 2.1 물리적 관점 vs 논리적 관점
| 관점 | 기준 | 보이는 형태 |
| --- | --- | --- |
| **물리적 관점** | 저장매체 내부 구조, 섹터, 0/1 데이터 | Element-level |
| **논리적 관점** | 사용자가 보는 폴더와 파일 구조 | Top-down |
## 2.2 섹터와 클러스터
| 개념      | 핵심                            |
| ------- | ----------------------------- |
| **MBR**     | 디스크 첫 섹터 512B, **파티션**/부팅 정보 저장   |
| **Sector**  | 저장장치의 물리적 최소 단위, 보통 512B      |
| **Cluster** | **파일시스템**의 할당 단위, 여러 섹터를 묶은 논리 단위 |
- 파일은 클러스터 단위로 저장되며, 파일 크기와 무관하게 최소 1클러스터를 차지한다.
- 포맷 시 선택하는 `할당 단위 크기`가 클러스터 크기이다.
### 2.2.1 클러스터 크기에 따른 특성
| 구분 | 장점 | 단점 | 포렌식 관점 |
| --- | --- | --- | --- |
| 작은 클러스터 | 작은 파일 저장 시 공간 낭비 적음 | 관리 테이블 증가, 성능 저하 가능 | **슬랙 공간** 감소 |
| 큰 클러스터 | 관리 단순, 빠른 접근 가능 | 작은 파일 저장 시 공간 낭비 큼 | **슬랙 공간** 증가, 잔존 데이터 분석 대상 증가 |
## 2.3 슬랙 공간
```text
파일 크기 < 할당된 클러스터 크기 → 남는 공간 발생
```

| 구분 | 위치 | 포렌식 의미 |
| --- | --- | --- |
| **RAM Slack** | 마지막 섹터에서 실제 파일 데이터가 끝난 뒤 섹터 끝까지 | 메모리 임시 값이 남을 수 있음 |
| **File Slack** | 마지막 섹터 이후부터 할당된 클러스터 끝까지 | 이전 파일 데이터나 삭제 데이터 조각이 남을 수 있음 |
- 슬랙은 파일에 할당됐지만 실제로 사용되지 않은 공간이다.
- **파일시스템** 관점에서는 공간 낭비지만, 포렌식 관점에서는 잔존 데이터 분석 대상이다.
# 3. FAT 파일시스템
## 3.1 FAT 기본 개념
- **FAT**는 `File Allocation Table`의 약자이다.
- 각 클러스터의 상태와 다음 클러스터 번호를 기록하는 테이블이다.
- **FAT**는 NTFS 이전 세대 **파일시스템**이며, **파일시스템** 동작 원리를 이해하기 쉬운 모델이다.
- 자세한 내부 구조와 **FAT Entry** 값은 13주차에서 다룬다.
## 3.2 FAT 파일시스템 구성
| 영역 | 핵심 |
| --- | --- |
| **Boot Sector / Reserved Sector** | 부팅 및 **파일시스템** 관리 정보 |
| **FAT Table** | 클러스터 상태와 연결 정보 |
| **Root Directory** | 루트 디렉터리 엔트리 |
| **Data Area** | 실제 파일 데이터가 저장되는 클러스터 배열 |
## 3.3 FAT 기본 동작
- 저장 관리 단위는 클러스터이다.
- 파일이 여러 클러스터에 나뉘어 저장되면 **FAT** 테이블의 연결 정보를 따라 읽는다.
```text
2 → 3 → 6 → End
```
- 예시는 2번 클러스터에서 시작해 3번, 6번을 거쳐 파일 끝에 도달하는 흐름이다.
