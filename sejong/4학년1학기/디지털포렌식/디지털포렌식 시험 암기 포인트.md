# 디지털포렌식 시험 암기 포인트

시험 유형을 모를 때는 **정의, 비교, 절차, 구조, 포렌식 의미**를 먼저 외운다.  
이 노트는 주차별로 “시험에 나오면 바로 써야 하는 것”만 압축한 암기용 노트이다.

# 0. 전체 최우선 암기

## 0.1 시험에 자주 엮이는 큰 흐름
```text
증거 식별 → 수집/획득 → 보존 → 분석 → 보고/증언
```

## 0.2 모든 주차에 걸치는 핵심 문장
- 디지털 증거는 쉽게 복제·변조되므로 **해시값, 원본성, 무결성, Chain of Custody**가 중요하다.
- 포렌식 수집은 **원본 훼손 최소화**와 **수집 과정 기록**이 핵심이다.
- 분석은 단일 흔적만 보지 않고 **여러 아티팩트의 교차 검증**으로 결론을 낸다.
- 삭제 복구의 핵심은 “데이터가 즉시 사라졌는가?”가 아니라 **인덱스와 메타데이터가 얼마나 남았는가**이다.

# 1주차 디지털 포렌식 개관

## 1.1 반드시 외울 정의
- 디지털 포렌식은 디지털 흔적을 **수집, 보존, 분석, 보고**하여 사건을 밝히는 기술이다.
- 디지털 포렌식은 보이지 않는 데이터를 사람이 이해 가능한 증거로 현출하는 과정이다.

## 1.2 디지털 포렌식 5대 원칙
| 원칙 | 암기 포인트 |
| --- | --- |
| 정당성 | 적법한 절차로 증거를 수집해야 함 |
| 원본성 | 원본과 동일한 상태로 재현 가능해야 함 |
| 무결성 | 수집 이후 변조되지 않았음을 입증해야 함 |
| 신뢰성 | 검증된 도구와 전문성을 바탕으로 분석해야 함 |
| 연계 보관성 | 획득부터 제출까지 증거 취급 이력을 관리해야 함 |

암기문: **정원무신연**

## 1.3 디지털 포렌식 조사 7단계
1. 사전 준비
2. 증거 수집
3. 데이터 보존
4. 조사 분석
5. 정밀검토 및 보고
6. 법적 대응 및 증언
7. 사후 대응

암기문: **사수보분보고법사**

## 1.4 보안 패러다임
| 구분 | 핵심 |
| --- | --- |
| 경계보안 | 경계 통과 후 내부 사용자를 신뢰하는 전통적 방식 |
| 제로 트러스트 | Never Trust, Always Verify |

제로 트러스트 원칙:
- 중앙 집중 정책 관리
- 최소 권한
- 사용자/기기 인증 강화
- 통신/저장 데이터 암호화

## 1.5 목적별 포렌식 영역
| 영역 | 분석 대상 |
| --- | --- |
| 응용 프로그램 | 파일 포맷, 복구, 해시, 애플리케이션 흔적 |
| 시스템 커널 | 휘발성 데이터, 로그, 레지스트리 |
| 저장매체 | 디스크/메모리 복구, 이미징, 복제 |
| 네트워크 | 트래픽, 로그, 프로토콜, 원천지 추적 |

# 2주차 디지털 증거

## 2.1 디지털 증거 정의
- 0과 1로 구성된 디지털 데이터 중 **신뢰성을 보장하여 증거로 활용 가능한 정보**이다.

## 2.2 디지털 증거 분류
| 기준 | 구분 | 예시 |
| --- | --- | --- |
| 속성 | 내용물/보관증거 | 문서 내용, 이메일 내용, 사진/영상 내용 |
| 속성 | 특성정보/생성증거 | 파일명, 해시값, 타임스탬프, 파일 크기 |
| 생성 방식 | 자동 생성 증거 | 로그, 이벤트 기록, 메타데이터 |
| 생성 방식 | 인위적 생성 증거 | 문서, 이메일, 사진, 암호 데이터 |
| 지속성 | 휘발성 증거 | RAM, 프로세스, 네트워크 연결 |
| 지속성 | 비휘발성 증거 | 파일, 로그, 파일시스템, 저장매체 정보 |

## 2.3 디지털 증거 특성
| 특성 | 암기 포인트 |
| --- | --- |
| 매체 독립성 | 정보 자체가 본질이므로 원본/사본 구별이 어려움 |
| 비가시성/비가독성 | 도구로 해석해야 의미 파악 가능 |
| 변조/복제 용이성 | 해시값으로 원본성·무결성 입증 필요 |
| 대규모성/초국경성 | 증거가 여러 시스템·국가에 분산 가능 |

## 2.4 증거능력 vs 증명력
| 구분 | 의미 |
| --- | --- |
| 증거능력 | 법정에서 증거로 사용할 수 있는 법률상 자격 |
| 증명력 | 그 증거가 실제로 얼마나 믿을 만한지의 정도 |

판단 흐름:
```text
증거능력 판단 → 증명력 평가
```

## 2.5 법적 허용성 관련 키워드
| 키워드 | 핵심 |
| --- | --- |
| 위법수집증거배제원칙 | 위법하게 수집한 증거는 증거능력 없음 |
| 전문법칙 | 직접 경험하지 않은 진술 증거는 원칙적으로 증거능력 없음 |
| 전문법칙 예외 | 신용성 보장, 필요성, 원진술자 법정 진술 불가 등 |

## 2.6 증거능력 요건
| 요건 | 핵심 |
| --- | --- |
| 원본성 | 법정 제출 자료가 원 매체 데이터와 동일해야 함 |
| 무결성 | 수집, 이송, 분석, 제출 과정에서 변경이 없음을 입증 |
| 신뢰성 | 절차, 도구, 인력, 시설이 믿을 만해야 함 |

## 2.7 Chain of Custody
- 증거가 처음 발견된 시점부터 법정 제출까지 **누가, 언제, 어디서, 어떻게** 다뤘는지 기록하는 절차이다.
- 무결성과 신뢰성을 입증하는 핵심 근거이다.

# 3주차 저장매체 이미징 및 분석

## 3.1 디스크 이미징 vs 라이브 포렌식
| 구분 | 디스크 이미징 | 라이브 포렌식 |
| --- | --- | --- |
| 대상 | 비휘발성 저장매체 | 휘발성 데이터 |
| 예시 | HDD, SSD, 파일시스템 | RAM, 프로세스, 네트워크 연결 |
| 안정성 | 높음 | 낮음 |
| 긴급성 | 낮음 | 높음 |
| 손상 위험 | 낮음 | 높음 |

## 3.2 디스크 이미징
- 저장매체 전체를 **비트 단위**로 복제한다.
- **Bit Stream Image**라고도 한다.
- 원본 데이터뿐 아니라 **메타데이터, 삭제 데이터, 빈 공간 데이터**까지 포함한다.
- 훼손 우려 없이 반복 분석이 가능하다.

## 3.3 도구
| 도구 | 특징 |
| --- | --- |
| `FTK Imager` | GUI 기반 이미징/분석 도구 |
| `EnCase` | 수집과 분석 기능 제공 |
| `dd`, `dcfldd` | CLI 기반 비트 단위 복제 |
| `Autopsy` | GUI 기반 분석, Sleuth Kit 활용 |

## 3.4 실습 명령어 흐름
| 단계 | 명령어/작업 | 의미 |
| --- | --- | --- |
| 디스크 확인 | `fdisk -lu` | 대상 디스크와 저장용 디스크 식별 |
| 대상 데이터 생성 | `dd if=/dev/urandom of=/dev/sdb count=2` | 분석용 디스크 준비 |
| 저장 디스크 초기화 | `dd if=/dev/zero of=/dev/sdc bs=16K` | 이미징 저장 준비 |
| 파일시스템 생성 | `mke2fs` | `ext2` 생성 |
| 원본 해시 | `sha256sum /dev/sdb` | 원본 무결성 기준값 |
| 이미징 | `dd if=/dev/sdb of=inspect1.img bs=16K` | 비트 단위 이미지 생성 |
| 이미지 해시 | `sha256sum inspect1.img` | 원본/사본 해시 비교 |

## 3.5 FTK Imager에서 볼 것
- 삭제 파일은 `X` 아이콘으로 표시될 수 있다.
- MAC Time: 수정, 접근, 생성 시간.
- Hex View로 파일 원시 데이터를 확인한다.
- 이미지 생성 로그에는 해시값, 사건 번호, 조사자 정보 등이 기록된다.

# 4주차 스테가노그래피

## 4.1 정의와 구성요소
| 용어 | 의미 |
| --- | --- |
| 스테가노그래피 | 데이터가 존재한다는 사실 자체를 숨기는 정보 은닉 기술 |
| Carrier | 데이터를 숨길 매개체 |
| Payload | Carrier 안에 실제로 숨기는 비밀 데이터 |

## 4.2 크립토그래피 vs 스테가노그래피
| 구분 | 핵심 |
| --- | --- |
| 크립토그래피 | 내용은 숨기지만 암호화된 데이터의 존재는 보임 |
| 스테가노그래피 | 데이터 존재 자체를 숨김 |

## 4.3 LSB 기법
- RGB 각 색상은 0~255, 즉 8bit이다.
- 한 픽셀은 보통 `R8 + G8 + B8 = 24bit`이다.
- **최하위 비트(LSB)**를 조작해 비밀 데이터를 삽입한다.
- 사람 눈은 1~2 정도의 색상 값 변화를 거의 구별하지 못한다.

## 4.4 삽입/추출 원리
```text
문자 → ASCII 코드 → 2진수 → RGB LSB에 1비트씩 삽입
```

추출은 반대 방향이다.
```text
RGB LSB 추출 → 8비트씩 묶기 → ASCII 문자 복원
```

## 4.5 한계와 고급 기법
- 단순 LSB는 통계 분석으로 탐지될 수 있다.
- 과도하게 삽입하면 육안으로도 티가 날 수 있다.
- 고급 기법: `HUGO`, `WOW`, `S-UNIWARD`

# 5주차 디지털 수

## 5.1 진법과 단위
| 항목 | 암기 |
| --- | --- |
| bit | 0 또는 1 하나 |
| Byte | 8bit |
| 16진수 1자리 | 4bit |
| 1Byte 표현 범위 | 0~255 |

포렌식에서 16진수를 많이 쓰는 이유:
- 2진수보다 사람이 읽기 쉽다.
- 2진수 4bit와 16진수 1자리가 1:1 대응된다.
- Raw Data 표현에 적합하다.

## 5.2 Big-Endian vs Little-Endian
| 구분 | 저장 방식 | 특징 |
| --- | --- | --- |
| Big-Endian | 큰 자릿값 바이트 먼저 | 사람이 읽는 순서와 유사, 네트워크에서 자주 사용 |
| Little-Endian | 작은 자릿값 바이트 먼저 | Intel/AMD 계열 해석 시 중요 |

## 5.3 음수 표현
| 방식 | 핵심 | 한계/특징 |
| --- | --- | --- |
| 부호-크기 | 최상위 비트를 부호로 사용 | +0/-0 문제 |
| 1의 보수 | 비트 반전 | 0이 두 개 |
| 2의 보수 | 비트 반전 후 1 | 현대 컴퓨터 표준, 뺄셈을 덧셈으로 처리 |

## 5.4 소수 표현
| 방식 | 핵심 |
| --- | --- |
| 고정 소수점 | 부호, 정수부, 소수부 위치 고정 |
| 부동 소수점 | 부호, 지수, 가수로 표현 |

부동 소수점 구조:
```text
Sign + Exponent + Mantissa
```

# 6주차 디지털 데이터 해석

## 6.1 Base64
- 바이너리 데이터를 안전한 문자 형태로 변환하는 인코딩 방식이다.
- URL, HTTP 요청, 검색 쿼리처럼 특수문자나 공백이 문제가 되는 환경에서 사용된다.

## 6.2 문자 코드
| 구분 | 핵심 |
| --- | --- |
| ASCII | 7비트, 128개 기호 |
| Extended ASCII | 8비트, 256개 기호 |
| Unicode | 전 세계 문자 통합 표준 |
| UTF-8 | 1~4바이트 가변 길이 |
| UTF-32 | 4바이트 고정 길이 |
| EUC-KR | 국내 환경에서 많이 쓰인 2바이트 계열 한글 인코딩 |

## 6.3 시간 기준
| 기준 | 내용 |
| --- | --- |
| GMT | 경도 0도 기준 평균 태양시 |
| UTC | 국제 표준시, 원자 시계 기반 |
| KST | UTC+9 |

## 6.4 파일시스템 시간
| 파일시스템 | 시간 방식 | 핵심 |
| --- | --- | --- |
| FAT | MS-DOS Date/Time | 2초 단위 정밀도, 1980년 기준 |
| NTFS | FILETIME | 1601-01-01 UTC 기준, 100나노초 단위 |

주의:
- 시스템 시간이 실제 시간과 다를 수 있다.
- UTC/KST 변환을 확인해야 한다.
- Little-Endian이면 바이트 순서를 뒤집어 해석해야 할 수 있다.

## 6.5 파일 시그니처
- 파일 내부의 고유 패턴으로 실제 파일 종류를 식별한다.
- 확장자는 쉽게 바꿀 수 있으므로 내부 구조와 시그니처를 봐야 한다.

파일 포맷 구조:
```text
Header → Metadata → Body
```

활용:
- 확장자 위장 탐지
- 손상/삭제 파일 복구 판단
- 파일 카빙 기준

# 7주차 DF 관점 컴퓨터 시스템

## 7.1 컴퓨터 시스템 계층
| 계층 | 포렌식 의미 |
| --- | --- |
| 하드웨어 | 장치 구성, 저장 매체 흔적 |
| 운영체제 | 로그, 레지스트리, 파일시스템 흔적 |
| 애플리케이션 | 실행 기록, 문서, 캐시, 설정 파일 |
| 사용자 | 계정별 행위 추적 |

## 7.2 부팅 기본 흐름
```text
전원 공급 → BIOS/UEFI → POST → OS Kernel 로딩 → RAM 적재 → 시스템 제어권 전달
```

## 7.3 휘발성 vs 비휘발성
| 구분 | 예시 | 포렌식 의미 |
| --- | --- | --- |
| 휘발성 | RAM | 전원 차단 전 우선 수집 |
| 비휘발성 | HDD, SSD, ROM, Flash | 이미징과 파일시스템 분석 대상 |

## 7.4 RAM/ROM/Flash
| 구분 | 핵심 |
| --- | --- |
| DRAM | 주기적 재충전 필요, 일반 PC 메모리 |
| SRAM | 빠르고 비쌈, CPU 캐시 |
| ROM | 비휘발성, 펌웨어 저장 |
| Flash | 전기적으로 지우고 쓰는 비휘발성 메모리 |
| NOR Flash | 빠른 읽기, 펌웨어 저장 |
| NAND Flash | 대용량 저장, SSD/USB/SD 카드 |

## 7.5 SSD 포렌식 주의점
| 기능 | 의미 | 포렌식 영향 |
| --- | --- | --- |
| Wear Leveling | 기록 위치를 분산해 셀 수명 연장 | 논리 주소와 물리 위치가 단순 대응되지 않을 수 있음 |
| TRIM | 삭제 블록을 SSD 컨트롤러에 알림 | 삭제 데이터 복구 가능성이 낮아질 수 있음 |

## 7.6 RAID
| 레벨 | 방식 | 장점 | 한계 |
| --- | --- | --- | --- |
| RAID 0 | 스트라이핑 | 속도 향상 | 디스크 하나만 고장 나도 전체 손실 |
| RAID 1 | 미러링 | 복구 안정성 | 사용 가능 용량 감소 |
| RAID 5 | 스트라이핑 + 패리티 | 속도와 안정성 균형 | 최소 3개 디스크 필요 |
| RAID 1+0 | 미러링 + 스트라이핑 | 속도와 안정성 모두 확보 | 비용 증가 |

## 7.7 숨겨진 영역
| 구분 | 의미 |
| --- | --- |
| HPA | Host Protected Area, 디스크 끝부분 예약 숨김 영역 |
| DCO | Device Configuration Overlay, 제조사 수준에서 용량/기능 제한 |

이미징 전 HPA/DCO를 확인하지 않으면 증거 영역이 누락될 수 있다.

## 9.4 논리 키와 실제 Hive 파일
| 논리 키 | 실제 Hive 파일 / 의미 |
| --- | --- |
| `HKLM\SYSTEM` | `C:\Windows\System32\Config\SYSTEM` |
| `HKLM\SOFTWARE` | `C:\Windows\System32\Config\SOFTWARE` |
| `HKLM\SAM` | `C:\Windows\System32\Config\SAM` |
| `HKLM\SECURITY` | `C:\Windows\System32\Config\SECURITY` |

# 10주차 활성화 시스템 분석

## 10.1 라이브 포렌식 정의
- 구동 중인 시스템에서 데이터를 수집하고 분석하는 기술이다.
- 꺼지면 사라지는 휘발성 데이터를 확보하는 것이 핵심이다.

## 10.2 라이브 포렌식 절차
```text
시스템 상태 확인 → 메모리 이미지 획득 → 시스템 기본 정보 수집 → 비휘발성 데이터 수집
```

이 순서의 이유:
- 도구 실행 전 현장 상태를 먼저 기록한다.
- RAM은 전원 차단과 명령 실행에 가장 민감하므로 먼저 덤프한다.
- 명령어 기반 수집은 시스템 상태를 바꿀 수 있으므로 메모리 덤프 뒤에 수행한다.
- 디스크/로그/레지스트리는 상대적으로 오래 남으므로 뒤로 간다.

## 10.3 수집 대상
| 구분 | 수집 대상 |
| --- | --- |
| 휘발성 데이터 | 시스템 시간, 프로세스/서비스, 로그인 사용자, 클립보드, 네트워크 연결, 열린 파일 |
| 비휘발성 데이터 | 파일시스템 메타데이터, 이벤트 로그, 레지스트리, 디스크 정보, 브라우저 기록 |

## 10.4 도구

| --- | --- |
| `DumpIt` | 메모리 덤프 |
| `Volatility` | 메모리 덤프 분석 |
| `Rekall` | 메모리 분석 |
| `Sysinternals Suite` | 프로세스, 네트워크, 파일, 레지스트리 확인 |
| `Wireshark` | 네트워크 패킷 분석 |

# 11주차 디지털 증거 분석

## 11.1 데이터 획득 방식
| 방식 | 핵심 | 침습성 |
| --- | --- | --- |
| 물리적 획득 | 저장장치 전체를 비트 단위로 접근 | 방식에 따라 다름 |
| 논리적 획득 | OS/파일시스템이 인식하는 파일 중심 | 낮음 |
| CHIP-OFF | 저장 칩을 분리해 추출 | 침습적 |
| JTAG | 디버깅 포트로 저수준 접근 | 비침습적에 가까움 |

암기:
- `CHIP-OFF`와 `JTAG`는 주로 스마트폰/IoT/임베디드 장치의 비휘발성 저장 데이터 획득에 사용된다.
- `CHIP-OFF = 칩 분리 = 침습적`
- `JTAG = 디버깅 포트 = 비침습적에 가까움`

## 11.2 획득 시 고려 사항
- 대상 장치 종류: PC, 서버, 스마트폰, IoT, 복합기
- 내장 메모리, SD 카드, USIM 등 분리 저장매체 확인
- 네트워크 연결 차단: 원격 삭제/잠금/변경 방지
- 도구, 옵션, 수집 범위가 다르면 해시값이나 결과가 달라질 수 있다.

## 11.3 검색/통계/시각화
```text
검색 → 통계 → 시각화
```

| 기술 | 의미 |
| --- | --- |
| 일반 검색 | 키워드, 파일명, 속성, 내부 문자열 검색 |
| 해시 검색 | 알려진 파일 해시 DB와 비교, 정상 파일 제외 |
| 슬랙 검색 | Slack Space에서 잔존 데이터 탐색 |
| 통계 | 시간별, 요일별, 파일 종류별 패턴 파악 |
| 시각화 | 타임라인, 그래프, 차트로 결과 표현 |

# 12주차 파일시스템 이해 1

## 12.1 기본 구조
```text
디스크 → 파티션 → 파일시스템 → 파일 구조
```

## 12.2 MBR vs GPT
| 구분 | MBR | GPT |
| --- | --- | --- |
| 위치/구조 | 디스크 앞 512B | UEFI 기반 최신 파티션 |
| 용량 | 최대 2TB | 최대 9.4ZB |
| 파티션 수 | 최대 4개 | 사실상 제한 없음 |
| 안정성 | 앞부분 한 곳에 정보 저장 | 앞/뒤에 정보 저장, CRC 지원 |
| 식별 | `0x55AA` | GUID |

MBR 구조:
```text
Boot Code 445B + Partition Table Entry 64B + Signature 2B
```

## 12.3 섹터와 클러스터
| 개념 | 의미 |
| --- | --- |
| 섹터 | 저장장치의 물리적 최소 단위, 보통 512B |
| 클러스터 | 여러 섹터를 묶은 파일시스템의 논리적 할당 단위 |

## 12.4 클러스터 크기
| 구분 | 장점 | 단점 | 포렌식 관점 |
| --- | --- | --- | --- |
| 작은 클러스터 | 공간 낭비 감소 | 관리 테이블 증가, 성능 저하 가능 | 슬랙 공간이 상대적으로 줄어듦 |
| 큰 클러스터 | 관리 용이, 빠른 접근 가능 | 작은 파일 저장 시 공간 낭비 증가 | 슬랙 공간이 커져 잔존 데이터가 남을 수 있음 |

## 12.5 슬랙 공간
| 구분 | 의미 |
| --- | --- |
| RAM Slack | 마지막 섹터에서 실제 파일 데이터 뒤부터 섹터 끝까지 |
| File Slack | 마지막 섹터 이후부터 할당된 클러스터 끝까지 |

포렌식 의미:
- 파일에 할당됐지만 실제로 사용되지 않은 공간이다.
- 이전 파일 데이터나 삭제 데이터 조각이 남을 수 있다.

## 12.6 FAT 기본 구조
```text
Boot Sector → Reserved Sector → FAT Table → Root Directory → Data Area
```

FAT의 핵심:
- `FAT = File Allocation Table`
- 클러스터의 상태와 다음 클러스터 번호를 기록한다.
- 파일 읽기는 FAT 체인을 따라간다.

# 13주차 파일시스템 이해 2

## 13.1 FAT 전체 구조
```text
Boot Sector → Reserved Sector → FAT1/FAT2 → Root Directory → Data Area
```

| 영역 | 핵심 |
| --- | --- |
| Boot Sector | BPB, Boot Code 포함 |
| Reserved Sector | FAT 시작 전 예약 공간 |
| FAT1 | 메인 FAT |
| FAT2 | 백업 FAT |
| Root Directory | Directory Entry 저장 |
| Data Area | 실제 파일/폴더 데이터 저장 |

## 13.2 FAT Entry 값
```text
0x00000000 → 비어 있는 클러스터
다음 클러스터 번호 → 연결 정보
0x0FFFFFFF → EOF
```

## 13.3 Directory Entry
저장 정보:
- 파일명
- 확장자
- 속성
- 생성/수정 시간
- 시작 클러스터 번호
- 파일 크기

외울 것:
- Directory Entry 크기: 32바이트
- Short File Name: 8.3 규칙
- LFN: Long File Name, 유니코드, 여러 Directory Entry 사용
- `Attribute = 0x0F`: LFN 엔트리
- `Attribute = 0x20`: 일반 파일 엔트리

## 13.4 FAT 파일 생성
예시:
- 클러스터 크기: 4096B
- `file1.dat`: 6000B
- 필요한 클러스터: 2개

흐름:
```text
Directory Entry 탐색
→ FAT에서 빈 FAT Entry(0x00) 검색
→ 190번 클러스터 할당
→ 남은 1904B 저장을 위해 191번 클러스터 할당
→ FAT[190] = 191
→ FAT[191] = 0x0FFFFFFF
→ Directory Entry에 시작 클러스터 190 기록
```

구분 주의:
| 표현 | 영역 | 의미 |
| --- | --- | --- |
| Directory Entry의 `0xE5` | Directory Entry | 삭제된 파일 정보 자리 |
| Directory Entry의 `0x00` | Directory Entry | 새 파일 정보를 적을 빈 자리 |
| FAT Entry의 `0x00` | FAT Table | 데이터를 저장할 빈 클러스터 |

## 13.5 FAT 파일 삭제
| 영역 | 삭제 시 변화 | 복구 단서 |
| --- | --- | --- |
| FAT 엔트리 | 사용하던 클러스터 엔트리를 `0x00`으로 초기화 | 연결 정보는 사라지지만 연속 저장 파일은 복구 가능 |
| Directory Entry | 파일 이름 첫 글자를 `0xE5`로 변경 | 파일 크기, 시간, 속성, 시작 클러스터가 남을 수 있음 |
| Data Area | 실제 데이터는 즉시 삭제되지 않음 | 덮어쓰기 전까지 복구 가능 |

핵심:
- FAT 삭제는 실제 데이터를 지우는 것이 아니라 **인덱스 정보를 바꾸는 것**이다.
- 연속 저장 파일은 시작 클러스터와 파일 크기만으로 복구가 쉽다.
- 조각난 파일은 다음 클러스터 추정이 필요해 복구가 어렵다.
- 덮어쓰기 발생 시 복구가 불가능해질 수 있다.

## 13.6 NTFS 특징
| 항목 | 핵심 |
| --- | --- |
| VBR | Volume Boot Record, BPB와 부트 코드 포함 |
| MFT | Master File Table, 파일/디렉토리 메타데이터 핵심 |
| `$BITMAP` | 사용/미사용 엔트리 또는 클러스터 관리 |
| `$DATA` | 실제 데이터 속성 |
| `$LogFile` | 변경 사항 기록 |
| `$UsnJrnl` | 변경 저널 |

NTFS 주요 특징:
- FAT의 테이블 역할을 MFT가 수행한다.
- 하나의 파일은 하나의 MFT 엔트리로 관리된다.
- 주요 속성: `STANDARD_INFORMATION`, `FILE_NAME`, `DATA`
- ADS, EFS, BitLocker, VSS 지원

접근 흐름:
```text
VBR → BPB에서 MFT 시작 위치 확인 → $MFT 접근 → $DATA로 구조 파악 → 파일/디렉토리 탐색
```

## 13.7 파일 카빙
- 메타데이터 없이 파일을 복구하는 기법이다.
- 파일 시그니처 기반으로 복구한다.
- 시그니처는 보통 **Header와 Footer**를 의미한다.
- JPG, GIF 등 고유 패턴을 활용한다.

# 헷갈리기 쉬운 비교

| A | B | 구분 포인트 |
| --- | --- | --- |
| 원본성 | 무결성 | 원본성은 원 매체와 동일함, 무결성은 수집 후 변경 없음 |
| 증거능력 | 증명력 | 증거능력은 법정 사용 자격, 증명력은 믿을 만한 정도 |
| 디스크 이미징 | 라이브 포렌식 | 비휘발성 전체 복제 vs 휘발성 실시간 수집 |
| 물리적 획득 | 논리적 획득 | 저장매체 전체/저수준 접근 vs OS가 인식하는 파일 중심 |
| CHIP-OFF | JTAG | 칩 분리 침습 방식 vs 디버깅 포트 비침습에 가까운 방식 |
| 크립토그래피 | 스테가노그래피 | 내용 은닉 vs 존재 은닉 |
| Big-Endian | Little-Endian | 큰 자릿값 먼저 vs 작은 자릿값 먼저 |
| 섹터 | 클러스터 | 물리 최소 단위 vs 파일시스템 할당 단위 |
| RAM Slack | File Slack | 마지막 섹터 내부 잔여 vs 마지막 섹터 이후 클러스터 끝까지 |
| Directory Entry의 `0x00` | FAT Entry의 `0x00` | 새 파일 정보를 적을 빈 자리 vs 데이터를 저장할 빈 클러스터 |
| FAT | NTFS | 클러스터 연결 테이블 중심 vs MFT 중심 |
| MBR Boot Code | FAT Boot Sector Boot Code | 부팅 파티션 찾기 vs 파티션 내부 부트로더 찾기 |
| HPA | DCO | 디스크 끝 예약 숨김 영역 vs 제조사 수준 용량/기능 제한 |
