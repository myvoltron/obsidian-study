# 1. 스토리지와 데이터 획득 이슈
## 1.1 증거 획득 전 확인 사항
디지털 증거 획득은 대상 장치, 저장매체 구조, 도구, 옵션, 획득 기법에 따라 결과가 달라질 수 있다.

| 확인 대상 | 핵심 |
| --- | --- |
| 장치 종류 | PC, 서버, 스마트폰, IoT, 복합기 등 |
| 저장 위치 | 내장 메모리, 외부 저장장치, SD 카드, USIM, 내부 캐시 |
| 네트워크 상태 | 원격 삭제/잠금/변경 방지를 위해 차단 필요 |
| 수집 범위 | 전체 디스크, 파티션, 파일시스템, 특정 파일, 숨겨진 영역 포함 여부 |
| 도구/옵션 | 도구와 옵션이 다르면 수집 범위와 해시값이 달라질 수 있음 |
## 1.2 데이터 획득 기법
| 기법 | 방식 | 침습성 | 장점 | 한계 |
| --- | --- | --- | --- | --- |
| **물리적 획득** | 저장장치 전체를 비트 단위로 추출 | 방식에 따라 다름 | 삭제/숨김 데이터까지 확보 가능 | 시간 소요, 장치별 난이도 차이 |
| **CHIP-OFF** | 저장 칩을 장치에서 분리 후 직접 읽음 | **침습적** | 파손/침수 장치에서도 가능성 있음 | 장치 손상 위험, 전문 장비 필요 |
| **JTAG** | 칩의 디버깅 포트로 접근 | **비침습적**에 가까움 | 칩 분리 없이 저수준 접근 가능 | 포트가 숨겨지거나 비활성화될 수 있음 |
| **논리적 획득** | OS/파일시스템이 인식하는 영역 수집 | **비침습적** | 빠르고 장치 손상 위험 낮음 | 삭제 데이터/숨겨진 영역 누락 가능 |
| **부트로더 활용** | OS 부팅 전 파티션 접근 | **비침습적** | 보안 설정에 따라 파티션 이미지 획득 가능 | 잠금 상태와 보안 정책 영향 큼 |
| **플래싱 도구** | 펌웨어/파티션 이미지 읽기 또는 기록 도구 활용 | **비침습적**에 가까움 | 일부 잠금 장치에서도 획득 가능성 있음 | 장치별 도구 의존도 높음 |
### 1.2.1 CHIP-OFF 절차
```text
기기 분해 → 메모리 칩 추출 → 칩 클리닝/마운트 → 데이터 추출
```
### 1.2.2 JTAG 절차
```text
JTAG 핀 식별 → JTAG 리더기 연결 → Pin Emulation으로 데이터 추출
```
## 1.3 획득 시 주의점
- **원본성** 입증을 위해 사용 도구, 옵션, 대상, 범위, 방식을 기록한다.
- PC/서버는 전체 디스크 이미징 절차와 연결된다.
- 스마트폰은 내장 메모리, 외부 카드, USIM, 네트워크 차단 여부를 함께 확인한다.
- IoT/복합기는 내부 저장매체, 로그, 설정, 저장 파일도 분석 대상이 될 수 있다.
# 2. 검색/통계/시각화 기술
## 2.1 왜 필요한가
- 저장매체가 대용량화되어 전체 데이터를 전수조사하기 어렵다.
- **검색**, **통계**, **시각화**는 사건 관련 데이터를 선별하고 분석 결과를 설명 가능한 형태로 만드는 기술이다.
```text
검색 → 통계 → 시각화
```

| 단계 | 역할 |
| --- | --- |
| **검색** | 사건 관련 데이터 선별, 불필요한 데이터 제외 |
| **통계** | 시간, 요일, 파일 종류 등 기준별 패턴 분석 |
| **시각화** | 타임라인, 그래프, 차트로 결과 전달력 향상 |
## 2.2 검색 기술
| 구분 | 핵심 | 예시/주의점 |
| --- | --- | --- |
| **일반 검색** | 문자열, 파일명, 속성, 파일 내부 문자열 **검색** | 인코딩과 바이너리 형태 고려, `grep`, OS indexing |
| **해시 검색** | 알려진 파일 해시 DB와 비교 | 정상 파일 제외, 악성/불법 파일 식별, NSRL |
| **슬랙 검색** | Slack Space 탐색 | 삭제/잔존 데이터 식별 |
## 2.3 통계와 시각화
| 기술 | 분석 포인트 |
| --- | --- |
| **통계** 분석 | 시간대별, 요일별, 파일 종류별 집계 |
| 타임라인 **시각화** | 파일 접근/수정 시간을 시간 순으로 재구성 |
| 사용 패턴 분석 | 컴퓨터 사용 시간, 주말 사용 여부, 특정 시간대 접근 여부 추론 |
# 3. 시스템 로그와 안티 포렌식
## 3.1 시스템 로그
**시스템 로그**는 시스템과 사용자 행위를 시간 순서로 기록하는 디지털 블랙박스이다.

| 로그 | 확인 내용 |
| --- | --- |
| Linux/Unix `acct` / `pact` | 사용자 명령 실행 기록 |
| `lastlog` | 최근 로그인 기록 |
| `loginlog` | 로그인 실패, 비정상 로그인 시도 |
| `messages` | 시스템 메시지, 부팅 메시지, 오류 |
| `sulog` | `su` 명령어 사용, 권한 전환 시도 |
| Windows 보안 로그 | 로그인 성공/실패, 파일 접근, 보안 이벤트 |
| Windows **시스템 로그** | 부팅, 장치 연결, 오류 |
| Windows 응용 프로그램 로그 | 프로그램 오류, 실행 상태, 경고 |
| 웹 로그/웹 아티팩트 | 방문 기록, 캐시, 쿠키, 브라우저 사용 흔적 |
## 3.2 안티 포렌식
**안티 포렌식**은 증거의 발견, 복구, 분석을 방해하거나 무력화하기 위한 기술이다.

| 기법 | 핵심 |
| --- | --- |
| 데이터 영구 삭제 | 복구할 수 없도록 삭제, Disk Wiping |
| **Degausser** | 강한 자기장으로 자기 저장매체 데이터 파괴 |
| 자동 삭제 프로그램 | 조건/주기에 따라 데이터 삭제 또는 덮어쓰기 |
| **암호화** | 키 없이는 내용 확인 어려움 |
| **스테가노그래피** | 데이터 존재 자체를 숨김 |
### 3.2.1 디스크 덮어쓰기
| 방식 | 핵심 | 한계/효과 |
| --- | --- | --- |
| **단순 0 덮어쓰기** | 디스크 영역을 0으로 덮음 | 단일 패턴이라 복구 회피 측면에서 한계 가능 |
| **다중 덮어쓰기** | 서로 다른 패턴으로 반복 기록 | 복구 가능성 감소 |
목적:
- 물리적 잔존 데이터 제거
- 삭제 데이터 복구 가능성 감소
- 포렌식 분석 난이도 증가
